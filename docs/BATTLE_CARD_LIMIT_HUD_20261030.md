# 小国戦線III｜試合中の使用回数上限UI改善（2026-10-30）

## 本人の新しいフィードバック
「試合中も正直召喚上限のUI影薄いからそこは改善した方がいいかも」

## 今回開発ブランチへ反映した改善
- 旧表示：手札カード最下段の小さな `残 3` または `∞`。残数の分母がないため、いつ尽きるか判別しづらかった。
- 新表示：カード下段の高コントラストなバッジに **`残り 3/4`** を表示。カードの最下段に使用回数の割合の短いゲージを追加。カードタイプ・占領アイコンは残す。
- **残り1回**＝赤系、**残り2回かつ既に一部使っている**＝黄系、通常＝青緑系、基本歩兵無制限＝緑系（`∞`）。
- エネルギー不足でも使用回数を読めるよう、従来のカード全体の暗転をやめて**カード絵・名前・コストを暗くしつつ残数は常に可読**にした。選択中のカードの枠線は維持。
- iPad / 小画面 / 横向き低高さ向けに、小さなバッジ・ゲージの調整をCSSに追加。戦場のカメラ・手札のタップ面積・体数上限・戦闘ルールは変更していない。
- アクセシビリティ：カードの`aria-label`にも「残りN回 / 上限M回」（基本歩兵は無制限）を付与。
- 同じCSSを `online.html`、`online-ipad.html`、`online-embed.html` に反映し、単体HTMLのJavaScriptを現行ソースへ同期。モジュール版には`online-game.js?v=22`と`online-deck.js?v=3`のキャッシュ更新。
- `tests/online-smoke.cjs` に実際の`buildCards()`をDOMスタブで実行し、4/4・1/2・2/4・0/4・∞の可視状態、スペル・大型・資源不足・aria・バンドルCSSを確認する回帰テストを追加。

## 2026-10-31｜Chromium・代表サイズの表示レイアウト再現確認

- 2026-10-31に開発担当がGitHub実装のカードDOM・主要CSS寸法を照合し、それらを使った**再現用の独立した静的HTML**をローカルChromium（touch/pointer:coarse）で表示・スクリーンショット目視。**製品HTML全体の実レンダリングではない**ことに注意。
- 観察した5条件：1194×834（カード高さ145px/横幅203px）、1024×768（131px/169px）、820×480（98px/135px）、768×1024（158px/118px）、844×390（98px/140px）。
- 5枚の各カードのDOM要素境界を測定し、残数バッジがカード外へ出ない・残数ゲージがカード内に収まる・カード縦方向のscrollHeightがclientHeightを超えないことを確認。小さめの短辺480pxでもportrait約28pxが残った。画面スクリーンショットを実際に目視し、残り4/4、2/3、1/2、0/3、固定∞の表示バランスは大きく崩れていないと判断。
- **限界**：原作キャラのCanvas画像は再現静的HTMLではダミー。ネット対戦、実ゲームの描画・ステータス同期、iPad SafariのWebKit・Google Sites埋め込みの表示は未確認。CSSを部分再現した検査であるため合格を実機の完全な保証とはしない。
- 上記から追加の大きなUI変更は不要と判断し、問題が具体化しない限り戦闘ロジックとカード下部の構造を再変更しない。
