# 小国戦線III｜探索型BOT v0.1：20秒ロールアウトによるカード・配置比較

2026-10-18。ユーザーが「複数の行動を試して短い将来を比較するBOT」方向を承認したため、**最初の実際に動く探索エンジン**をQA専用で作成した。ロールアウトは本番BOTにまだ統合しない。

## どこに何を実装したか

- `tests/online-bot-rollout-search.inc.js`：localhost限定の戦況を複製し、実際のカード使用関数 `botUse` で合法な候補を1つずつ試し、実際の30Hz `tick(1/30)` を20秒回す。
- `tests/online-bot-rollout-search.cjs`：Playwrightで元の `online-game.js` をHTTP配信時だけ一時的に計測用拡張。**元ゲームファイルを書き換えず**、既存のQA `setBotScenario` と並んで `searchActions` を使えるようにする。各候補を同一開始盤面と固定seed 17/41/73で比較し、同じ検索を再度行って決定性を厳密照合。
- `.github/workflows/online-bot-rollout-search.yml`：CIとJSONアーティファクト。
- `online-game.js`／`online-embed.html`／`online-ipad.html`、通常BOT、オンライン通信、ゲーム性能・コスト、公開main：**変更0**。

実際の合法な自分の4枚手札と常設歩兵から、購入可能なユニットのみを対象にする。選択肢は「出さない」「既存の召喚境界付近へ出す」「目標砦のレーンへ出す」「城に接近中の敵の進路上、合法な迎撃位置へ出す」。同じ20秒の実エンジンで、城被害・敵ユニット被害・拠点占有時間・購入コスト等を**固定の暫定スコア**で比較。観測した敵位置と自分の合法な手札・資源だけから候補を生成し、敵の非公開カードを参照しない。通常BOTの実際の初手も比較用に採点する。

5つの固定場面について、3seed×合法カード候補6〜13種×20秒のゲーム内物理・攻撃・占領を分岐再生（各場面は決定性のため2回繰り返し）。比較は青軍ではなく赤軍BOT team2から開始した固定QAシーン。以下の被害・与ダメージは3seed平均値。

| 局面 | 従来BOTの選択と開始位置 | 探索で最も高評価の選択 | 従来/探索 自城ダメージ | 探索での既存敵へのダメージ |
| --- | --- | --- | ---: | ---: |
| 敵偵察2体が城方向へ突破中 | 衛士 x=854,y=205 | **衛士 x=1043,y=213**（合法な迎撃位置） | **896 / 0** | 390 |
| 飛行ドローン1体 | 射手 x=879,y=205 | 射手 x=1055,y=205 | 0 / 0 | 135 |
| 守備兵が存在し地上偵察が突破中 | 衛士 x=854,y=205 | **歩兵 x=1015,y=205** | **420 / 0** | 195 |
| 重戦車1体が接近 | ゴーレム x=854,y=205 | ゴーレム x=854,y=205 | 0 / 0 | 1100 |
| 敵不在の初期占領 | 偵察ライダー x=1071,y=205 | 基本歩兵 x=1071,y=205 | 0 / 0 | 0 |

**解釈**：衛士を出す「カードの種類」は正しくても、召喚境界の近く（x=854）ではもう敵がその先を突破していて、城を守れない例が発見された。カードと位置を同時に比較した結果、相手の進路に衛士を配置できる候補が見つかり、この固定シーンでは自城被害が896から0になった。既存の味方守備がある別場面でも、低コスト歩兵を適所に出す方が固定スコアは高かった。

一方、**敵不在の占領で偵察ライダーより基本歩兵を選ぶ**のは警戒対象。20秒しか見ないと、将来の高速前線確保や深い砦の戦術価値を軽視する可能性がある。探索が常に合理的になるわけではない。

## 必ず守る制約・弱点

1. **勝率改善は未証明。** 上表は5つの静的固定シーンでの自軍初手の20秒条件付き結果であり、実ゲームの数百戦・対人・未知seedの優位ではない。
2. ロールアウト中は**敵も味方も追加カードをプレイしない**。既に見える部隊の移動・攻撃・城・砦・資源回復は実物の30Hz処理だが、相手の反撃増援・手札循環・複数ターンの計画には対応していない。
3. 成果スコアの重みは開発用の暫定値であり、将来の勝率ではない。試行錯誤で同じ固定5場面だけに最適化して本番採用してはいけない。
4. 完全な公平さのため毎候補で開始ゲーム状態を複製しているが、行動別に戦闘で消費する擬似乱数順は分岐し得る。3seedの結果は一般化の統計ではない。
5. 現状は **team2と固定QA盤面** のみ。実戦中に毎秒や毎ターン使う計算時間、iPad Safariの負荷、マルチのホスト処理遅延をまだ評価していない。通常対戦UIでは一切呼ばれない。

## 次の工程（未完了、今後の指針）

- 相手の非公開手札を覗くことなく、公開資源・敵の実際の動きから**複数の合理的な反撃候補**をシミュレーションし、探索を都合の良い未来へ偏らせない。
- `wait` 以外の複数ターン選択と目標砦の長期価値を検討し、低コスト即買い一辺倒を避ける。
- 盤面・陣営交換、検索幅・深さ・計算時間の上限、同期ラグへの影響を検査する。
- 有望な設計ができたら **QA限定の同じ対戦条件で旧BOTと新BOTをペア比較**し、城HP・砦保持・勝敗・カード選択の変化を反証。合格まで本番のBOTとmainへは統合しない。

ここまでの実装は、従来の「新しいif条件を追加」の方向ではなく、**合法な異なるカードと配置場所を実際のゲームエンジンで前向きに比較する探索の基盤**である。
