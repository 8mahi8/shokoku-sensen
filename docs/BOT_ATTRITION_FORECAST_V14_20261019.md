# 小国戦線III｜V14 砦周辺の戦闘消耗予測研究・独立比較・実対戦への移行検証（2026-10-19）

## 結論

**軽量な消耗予測は「目の前の兵士だけ」の18秒戦闘には効果があったが、実際の完全試合への一般化は弱く、通常BOTには導入しない。**

- 事前に用意した18戦況×3HP設定×4seedの**開発216局所戦闘**：開始HPのみの予測MAE 0.5605 → V14 0.3630（35.2%低下）。
- 別に用意し係数を固定した14戦況×3HP設定×4新seedの**独立168局所戦闘**：MAE 0.4851 → **0.2679**（44.8%低下）。局所戦闘中はカード・スペルを新たに使わせず、元から存在する部隊だけの損耗を比較。
- **6新seed × 5戦術 × 2条件の60完全試合**から、自然発生した局所交戦を159個測定：MAE 0.3495 → **0.3385**（3.2%低下）。しかし勝勢・劣勢の3値分類の正解数は**80/118（旧）→76/118（新）で悪化**。
- 159観測区間のうち**149区間では敵が後からカードを使用**。スペル使用38区間のMAEは0.2210→**0.2901（31.3%悪化）**。スペルなし121区間では0.3898→**0.3537（9.3%改善）**。データ数と同一試合内の相関に注意。この差を「スペルだけが予測失敗の因果原因」とは断定しない。
- 砦所有は研究中に別ラベルとして追跡したが、V14は**まだ砦占領結果そのものを予測するモデルではない**。したがって砦を捨てる/守る判断にも使わない。

## 外部研究から導いた考え方

1. [Stanescu, Barriga, Buro (2015): Using Lanchester Attrition Laws for Combat Prediction in StarCraft](https://ojs.aaai.org/index.php/AIIDE/article/view/12780)。ユニット種類ごとの火力・現在HP、消耗に基づく安価な戦闘予測。既存戦術AIへ繋ぐ発想を参考にした。ただし**小国戦線のゲームルールはStarCraftと異なる**ため、論文の学習係数・勝率を転用していない。
2. [Predicting Army Combat Outcomes in StarCraft](https://www.researchgate.net/publication/285588950_Predicting_army_combat_outcomes_in_StarCraft)。単純な総HPとDPSだけでは不十分で、標的、武器能力とHPの組合せが重要という背景。
3. [MDN Performance.now()](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)：計算時間をブラウザ単調時計で測定した。単一のChromium/Linuxの参考値であり、iPad SafariのCPU速度を推測する根拠にはしない。

原論文のアルゴリズムそのものを移植したわけではない。**HP/DPSに距離・進撃方向・対空可否・守備役/占領役というゲーム固有の制約を加えた無学習のスコアモデル**。

## 実装（GitHub develop限定）

- `tests/online-bot-attrition-v14.inc.js`：`qaAttritionPredictionSnapshot`（砦周囲の現存可視部隊）、`qaAttritionForecast`（18秒間の残HP割合差を見積もる軽量な代理モデル）、`qaAttritionTrial`（QA内の同一30Hz実エンジンで事後の損耗・砦所有を計測）。
- `tests/online-bot-attrition-v14.cjs`＋`.github/workflows/online-bot-attrition-v14.yml`：開発用216・別構成の独立168局所戦闘。モデルの係数は最初から固定し、独立側のデータで再調整していない。敵軍を飛行させ、迎撃衛士だけでは攻撃できない局面、射手の対空、工兵の砦への優先行動、迎撃範囲と前線部隊などを区別。
- `tests/online-bot-attrition-v14-natural.inc.js`＋`tests/online-bot-attrition-v14-natural.cjs`＋対応Actions：実際の30Hzフルゲームで、32/52/72/92/112/132/152/172/192ゲーム秒の定点から18秒間の損耗を観測。予測時点で存在するUIDのHPを追い、新規召喚ユニットのHPをその元部隊に混ぜない。観測コードあり・なしを同seedで再試行し、終了勝敗、HP、カード、資源、砦時間、開始手札/キューが**60/60試合で完全一致**することを検証。
- `duelStats.actionLedger` の事後ラベルで、予測後の新しい敵味方カード・スペル発生の有無を分類。ただしこの未来のログは**予測モデルの入力には一切使用しない**。
- **オンライン公開ソース、BOT通常行動、カード能力・城HP・Firebase設定、iPad配布HTML、mainには変更なし。** localhost QAサーバがテスト時にのみJSに観測ヘルパーを一時注入。

## 厳密な予測対象

初期の砦近傍（|x−砦x| <=300、|y−砦y| <=215）で、生存する双方の部隊を取得。部隊ごとに現在HP、攻撃力/クールダウン、射程、速度、対空、行動役割、攻撃方向を参照。

V14は「この先18秒の間にどの程度の火力を相手に与えられるか」の近似から、各陣営の**予測残HP割合**を計算。予測目標は

`味方の初期部隊の残存HP割合 − 敵の初期部隊の残存HP割合`

であり、−1～+1の連続値。比較用の最も簡単な基準は

`（味方初期HP合計 − 敵初期HP合計）÷（両軍初期HP合計）`

というHPだけの符号付きスコア。これは別の性質の非常に弱い比較モデルなので、V14の改善率が「真の強力な既存予測手法に対して44%改善」の意味になるわけではない。

時限結果の勝勢・劣勢分類は、真の残HP割合差が+0.15超／−0.15未満の場合のみ「有意の勝勢・劣勢」、間を拮抗とする。集計での非拮抗標本数は独立局所ケース164、完全対戦の自然区間118。統計的な確信区間・相関補正は未実施。

## V14の採否・次に行うべきこと

**研究モデルとしては保持。通常BOTへの昇格・公開版変更は不採用。** 単純HP基準より改善した局所無増援戦闘の利用は将来あり得るが、以下の不足点がある。

1. **城・砦の価値は別モデル**：ユニット残HP比の差を当てても、前哨基地の占領や城ダメージレースに勝てるとは限らない。次は未来の勝敗情報に依存しない砦危険信号（占領部隊の進入ETA、迎撃の射程・残HP、味方の再配置・資源状況）を別ラベルで作成し、真の30Hz「砦を失ったか」に照合。
2. **戦闘以外に介入する事後イベントを区別**：敵が次に支出できるかは隠れたカードがあるため完全予測不可。現時点の可視敵エネルギー推定や敵の平均支出率など観測可能な範囲だけで「不確実性が高いので予測を使わない」を評価する。事後カード履歴をそのままBOTの入力にしてはいけない。
3. **スペルと範囲攻撃**：防護結界で被ダメージ減少、範囲砲撃で急な複数撃破。局所モデルに現在すでに存在するスペルを取り込むかどうか検証し、未確認の未来スペルを予言したことにしない。
4. **事前登録の継続**：現時点の観測された負けパターン（スペルあり、rush/fortressなど）に合わせてモデルを修正し、同じ6seedで再度優位を主張しない。新しいモデルの評価には別の未知データが必要。
5. **実際のBOT勝率とiPad**：戦力評価を使った行動分岐が設計できた後、同一シード・先後入替・複数敵スタイルで勝敗・城HP・砦保持・手札と資源・frame負荷を比較。学校iPad Safari/Google Sitesでの動作確認は別途必要。

**最後に、今回のモデルは一度も本物のBOT行動を変更していない。** QAの観測だけで「対戦BOTが強くなった」とは主張しない。
