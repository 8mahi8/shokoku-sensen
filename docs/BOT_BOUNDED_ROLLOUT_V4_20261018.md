# 小国戦線III｜探索型BOT v0.4 軽量化と反証（2026-10-18）

## 結論

**採用できる候補は「第2手の探索だけを最大5候補（待機＋4カード配置候補）に絞る」QA専用方式。第1手を最大6候補に削る方法は不採用。** 標準BOTと公開main、オンライン通信、iPad単体配布HTMLの実ゲームロジックは変更していない。

今までのルールベースBOTの反証：単純な大型貯蓄、低コスト歩兵の常時投入、近い砦への固定占領などは、訓練で一時的に良く見えても、未知条件で勝率が悪化し得た。今回も「短くなったので良い」と即採用せず、以前の研究と同じ対照比較で候補を落とす。

## 実装

- `tests/online-bot-rollout-bounded.inc.js`：既存の2手探索から、6秒後の合法な第2手候補を待機＋最大4個に制限。手札・自軍の資源、可視敵種類（飛行、大型、地上、城への接近）、合法な進路上の迎撃位置を使い、未来の隠れた手札・敵の+9秒追加召喚予定・未来の採点結果を使わず候補を選ぶ。第1手の候補は一切削らない。
- `tests/online-bot-rollout-bounded.cjs`：5固定場面×2既知seed×3仮想敵反応（idle/counterpush/latePush）で無制限版と同条件比較、ゲーム本来の30Hz `tick` を使用。
- `tests/online-bot-rollout-bounded-sweep.cjs`：敵/手札/砦/資源の組み合わせ24場面×2seed×2反応で、選択が本当に変わらないか追加検証。24場面は人工生成した局面であり、実際の独立holdout対戦ではない。
- `tests/online-bot-rollout-budget.inc.js`：比較のため、第1手まで待機・既存BOT案・可視状況から選ぶその他の合法案を合計最大6個に絞る研究候補。
- `tests/online-bot-rollout-budget-sweep.cjs`：同じ人工生成24場面で広い第1手と候補制限版を比較。欠点が見つかったので **不採用**。
- 各専用GitHub ActionsワークフローとJSON artifactを追加。実装ファイルは `tests/` の一時注入用JavaScriptのみ。

## 実測

**第2手のみの候補削減**：

[GitHub Actions #39126387686](https://github.com/8mahi8/shokoku-sensen/actions/runs/39126387686) **SUCCESS**。5固定場面で第1手一致 **5/5**、6秒後の第2手候補の30Hz計算フレーム **834,120 → 584,640（-29.9%）**、Chrome実行時間 **4,996.4ms → 3,207.8ms（約-35.8%）**。各ケースの最終第1手は一致したが、分岐内の第2手が全て同じとは限らず、評価スコアにも小さな差が生じた。これを同じ強さの証明として扱わない。

[GitHub Actions #39126559551](https://github.com/8mahi8/shokoku-sensen/actions/runs/39126559551) **SUCCESS**。人工生成24局面でも第1手一致 **24/24**、6秒後の評価候補数 **4,384 → 3,340（-23.8%）**、Chrome計測実行時間 **約10.89秒 → 約8.20秒（-24.7%）**。同じ既知seedのデバッグ場面であり、汎用BOTの勝率優位を保証しない。

**第1手まで削減**：

[GitHub Actions #39126748310](https://github.com/8mahi8/shokoku-sensen/actions/runs/39126748310) **SUCCESS**（テストが正常に完走したという意味）。人工生成24局面で、全候補からの第1手と一致 **19/24**、**5/24で不一致**。第2手候補評価回数4,384→2,536（-42.2%）、Chrome約6.36秒→約3.70秒（-41.8%）と速くなるが、敵の飛行＋地上複合局面で守護ゴーレムによる迎撃、別場面で攻城戦車や対空射手などの有効候補を落とした。固定評価スコア上、たとえば戦車が-大幅に不利な射手に取って代わる場面を確認。**速度では補えない戦術判断品質の低下があるため第1手の圧縮は否決**。結果を見て同じ24場面だけに閾値を後付け調整しない。

## 安全性・未検証

- すべて `develop` の研究用ファイル。通常BOT `botExpertAction`、ゲームJS、Google Sites埋め込みiPad HTML、公開mainは変更していない。
- ユーザー端末の学校iPad Safariでの測定は未実施。Chrome Linux CIの計算時間はSafariの性能ではない。300ms以上を要する探索をそのまま対戦中の同期処理で呼べば、フレーム落ち/操作遅延の危険がある。現時点で**まだオンラインの通常BOTへ統合してはいけない**。
- 実戦で30Hzの完全試合をBOT同士でA/B比較したわけではなく、未知シードの独立勝率試験もまだしていない。勝率改善は未証明。
- 手作りの評価スコアは真の勝率ではない。候補削減後の初手一致は良い回帰シグナルだが、あらゆる局面の強さを保証しない。
- 次は局面の一部だけを何段階かに分けて評価する計算予算の制御、必要なときだけ探索を発動するゲート、未観測情報を使わない軽量な代理評価、そして実試合のA/B比較を行う。いずれも独立holdoutの結果を調整に再利用しない。
