# 小国戦線III｜攻城12秒予測と実測照合 V4

2026-10-18 / `develop` 専用の観測テスト。**通常BOT、戦闘ロジック、公開main、ゲームカード数値を変えない**。

## 狙いと落とし穴
従来の`castleRaceValue`は、現在の味方部隊が敵城へ与えうる12秒攻城ダメージを「移動最短時間→攻撃速度→残HP比」で楽観的に見積もり、増援が必要か判断した。既知360試合では前版比で勝率改善0。特に予測が「本当に当たったのか」が未検証だった。

そこで未来のユニットを混ぜず、**予測時点で戦場に実在したユニットのUIDだけ**を追跡する。実際の`fire()`で敵城に命中した瞬間のダメージをUIDに帰属し、後から召喚された味方や他部隊のダメージは「otherDamage」に隔離する。城HPが0になったときの過剰攻撃も差分実ダメージで切り詰める。

## 計測仕様（挙動変更なし）
- `runDuel(..., variant="fortDefenseValue", auditForecast=true)` という**localhost ?qa=1 専用**引数で計測有効化。FALSEならこれまでの試合と同じ。戦術ポリシー、乱数、召喚、AI思考時間は一切変更しない。
- 各フル試合の開始60秒から12秒刻み、最大228秒で、攻城可能な現在の通常行動ユニット（HP50%以上、敵城壁面から510px以内）をスナップショット。現在位置・公開攻撃力/攻撃間隔/射程/移動速度/城ダメージ倍率・残HP比で**元の12秒予測式**を実行。
- 同じ12秒でその**同じUIDの城への実命中**だけ合算し、他ユニットの命中を別計上する。試合終了で12秒間観測できない予測は打切り（censored）として精度集計から除外。
- 計測の有無のみ違う**120対応条件×2＝240フルゲーム**を実行し、勝敗、試合時計、カード使用、初期手札、資源消費、砦保持時間が一致することをプログラムで強制検証。
- 既知6シード×両軍×5スタイル×2試合条件。独立holdoutシードは未使用。

## 受入基準
- 全120対照で計測ON/OFFが完全に同じゲーム結果、正常な命中帰属、12秒未完了の打切り識別。
- 予測>0のうち実命中0の率、実被害/予測、敵城の守備兵の有無、敵兵と先頭隊との距離による失敗差を計算。単なる総敵城HP減少を「既存部隊の成果」としてはいけない。
- 予測が信頼できないならV3のような楽観的戦略を通常BOTへ採用しない。具体的な誤差を確認してから予測精度改善の仮説を設計。都合よく既知シードに最適化しない。


## 実測結果（2026-10-18・既知シード研究）

計測ON/OFFの120対照条件・**240フルゲーム**の[Actions検証](https://github.com/8mahi8/shokoku-sensen/actions/runs/39109363536)は成功。すべての対照試合で使用カード、資源消費、勝敗、試合経過、砦保持時間が一致した。12秒窓723件のうち116件は試合終了のため打切り（精度集計に不使用）、607件は全12秒観測可能。

- 607完全窓のうち予測火力が正の窓は403件。うち**111件（27.5%）は元からいた対象部隊の攻城命中0**だった。逆に予測火力0で対象UIDが実命中した完全窓は0件。
- 予測あり403窓の予測総火力159,198に対して、**同じ予測時点の対象UIDの実ダメージ133,217**。予測平均395.0、実績平均330.6、平均絶対誤差96.24。標準の状態では先制火力を過大評価。
- 全607窓における敵城総ダメージ208,122のうち74,905（約36%）は対象スナップショット以外のユニットの命中であり、単に敵城HP差を実績として用いると帰属を誤る。
- 予測あり窓：敵城周辺230px内に敵守備兵がいる場合124窓、予測平均292.7／同部隊の実ダメージ平均92.7。**守備兵なし**279窓では予測平均440.5／実績平均436.3。
- 予測対象に170px以内で近い敵がいる場合164窓、予測平均317.4／実績平均153.1。近い敵がいない239窓は予測平均448.3／実績平均452.4。

### 補正モデルの既知シード交差検証

[再現テスト #39109610322](https://github.com/8mahi8/shokoku-sensen/actions/runs/39109610322) 成功。追加`tests/analyze-castle-forecast.cjs`は、既知6シードのうち1シードを評価用に抜き、他の5シードから「実績総ダメージ/予測総ダメージ」を算出（推定係数は0〜1.25倍にクリップ）。6シードを順番に検証側に回した。**分析の候補自体は既知データ観察後に決めているため、独立した未使用holdoutではない。**

| 補正方法 | 403窓の平均絶対誤差MAE | RMSE |
| --- | ---: | ---: |
| 元の12秒予測 | 96.24 | 158.72 |
| 全条件を同一係数で補正 | 123.44 | 162.35 |
| 敵城付近の守備兵の有無で係数を分ける | **62.44** | **103.42** |
| 対象部隊の近くの敵の有無で係数を分ける | 81.81 | 140.99 |
| 守備兵×近くの敵の組合せ（不足時は守備兵補正へフォールバック） | 63.21 | 106.33 |

守備兵有無による係数の研究上の傾向：守備兵ありで実/予測総ダメージ約0.317倍、守備兵なしで約0.990倍。全体のMAEが約35.1%減少。**ただし6シード中、41と73の2シードでは守備兵別補正のMAEが悪化**し、全シードで有効とはいえない。同じ試合中の複数窓は互いに相関する。

### 決定

**今回は正式BOTへの反映をしない。** 予測補正のMAE改善が実戦勝率改善を意味するわけではない。また現時点の守備兵フラグは静的な写真であり、予測後に発生する守備兵の召喚、途中で砦に寄る経路、攻撃対象切替などを予測していない。次の観測候補は、予測後12秒の防衛増援・攻撃中断・対象部隊生存時間が残差とどう結びつくかの追跡。未知のholdoutは保存し、勝敗実験は明確な価値仮説を作ってから行う。

公開mainと通常BOT、ゲームルール、iPad向け公開導線は不変。
