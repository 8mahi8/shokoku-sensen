# 小国戦線III｜城ダメージレースの増援到達価値 QA

2026-10-18 / develop専用。城への被害を合理的に許容し、勝ち切る判断を精密化するための研究。**通常BOTと公開mainには適用しない**。

## 仮説
旧`castleDamageRace`は自軍が有利な直近10秒の城ダメージレースで攻勢・温存を選ぶが、120条件の実測では衛士優先型に対し勝率差0。攻勢増援が敵城に届く前に決着する状況では、その召喚判断に価値がない可能性を検証する。

新`castleRaceArrival`は同じ過去の実ダメージによる判定を出発点にして、実際の手札・コスト・合法召喚線から非占領主体の攻撃部隊（ドローン・射手・制圧機兵・戦車）が**敵城の射程圏に入るまでの楽観的な下限秒数**を求める。最短到着が敵城の推定撃破まで3秒以上早く、自城の推定撃破まで6秒以上早い候補だけに限定し、最速候補から召喚する。既存攻勢部隊がHP35%以上を維持していることも要求する。到着不可能/遅すぎるときは**無条件に資源を温存せず衛士優先型の防衛/奪還判断へ戻す**。

この秒数は敵兵との接触や経路変更を含まない理論最短値であり、「必ず敵城に届く」という予測ではない。今回の距離・安全余裕・HP基準は仮説の初期値であり、既知シードで都合よく調整して勝率改善を作らない。

## 再現と採用基準
`tests/online-bot-castle-race-arrival.cjs` は固定QAシーンで旧戦術の戦車、新戦術の到着可能なドローン、到着が遅い場合の衛士防衛などを確認し、既知6シード×両軍×10状況×3政策＝360フル試合を同じ30Hzエンジンで実行する。比較対象：`fortDefenseValue`／旧`castleDamageRace`／新`castleRaceArrival`。

出力 `qa-bot-castle-race-arrival/summary.json`。勝敗、城HP、攻城ダメージ、砦所有、攻勢適用・防衛復帰を集計する。改善なし/劣化なら公開採用見送り。独立holdoutは最終の確認まで保存する。


## 実測結果と研究判定（2026-10-18）

到着時間比較: https://github.com/8mahi8/shokoku-sensen/actions/runs/39106312019 (SUCCESS)
資源不足診断: https://github.com/8mahi8/shokoku-sensen/actions/runs/39106498203 (SUCCESS)

どちらも既知6シード、両陣営、120対応条件×3戦術=360フルゲーム。同じ条件が複数回試行されており、判断382回は独立な標本382個を意味しない。

| 指標 | 実測 |
| --- | ---: |
| 自軍が有利な城ダメージレースだと判断 | 382回 |
| 新たな攻勢増援を召喚 | 0回 |
| 衛士優先型の防衛・奪還へ復帰 | 382回 |
| 攻勢カードが手札にない | 0回 |
| 攻勢カードは手札にあるが資源不足 | 382回 |
| 資源2未満 | 291回 |
| 資源2以上4未満 | 91回 |
| 基本歩兵なら召喚可能 | 92回 |
| 衛士優先型との勝敗差 | 0改善・0悪化 |
| 旧ダメージレース型との勝敗差 | 0改善・0悪化 |

固定局面では旧戦術は戦車、新戦術は到着可能なドローンを選び、到着が遅い・レース不利・履歴欠損・攻勢なしの場合は衛士を選んだ。

**解釈**: 実戦での直近の制約は追加戦力の移動時間ではなく、攻勢カードに必要な資源が残っていないこと。過去の命中と現存ユニットからの予測が正しくても、出せる戦力がなければ意思決定が変わらない。基本歩兵は安価でも攻城への到着が遅い可能性があり、必ず出すべきとは限らない。

**判定**: 現状の到着時間版は通常BOTに不採用。次段で研究すべきは、ダメージレースが顕在化する前に4資源以上を蓄える戦略と、防衛・奪還に使う資源との機会費用。既知シードでしきい値を過剰最適化せず、独立holdoutは最終検証用として温存。公開main・通常BOT・性能・ルールは不変更。
