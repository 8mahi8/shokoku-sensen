# 小国戦線III｜味方先鋒が敵城に到着する時間を加えた4資源予算 QA V2

2026-10-18 develop専用。以前の`castleRaceBudget`は比較対象として残し、`castleRaceBudgetGuarded`を別のQA候補として実装。通常BOT/公開mainは変更しない。

## V1の実試合が示す失敗
[初回360試合](https://github.com/8mahi8/shokoku-sensen/actions/runs/39107085242)では計画18回（16対照条件）、うちドローン投入6回、中断12回。衛士優先型比で勝敗改善0/悪化1、平均自城HP -15、平均敵城ダメージ -17.5、平均資源消費 +0.083。よって**V1は不採用**。

敗北した局面は既知シード131・RED・self戦（非ミラー）。従来`fortDefenseValue`はRED勝利・残城HP1800、新`castleRaceBudget`は敗北。計画開始87.23秒時、先頭の基本歩兵は敵城壁面から約482px離れていた。まだ攻城開始まで遠く、4資源の温存に必要な攻勢の確度はなかったと考えられる。ただしこの1局面だけで因果原因の断定はできない。

## V2の仮説と変更点
「攻勢部隊が敵城方向にいる」だけでなく、**現存部隊が敵城へ攻撃可能距離に入るまでの理想的な最短時間が12秒以内**である場合に限って12秒以内の短期資源保留を試す。距離・公開クラス射程・移動速度から求める。敵との戦闘、ルート変更、妨害は含めないためあくまで楽観的な下限。12秒はV1の貯蓄期限を超える局面で無理に予算を拘束しないための理論上の整合性基準（データに合わせた勝率最大化値ではない）。

通常BOTの防衛、迎撃、砦戦、使用可能カード、資源ルールは維持。適用対象はQAのみ。旧V1の戦術も履歴を残す。

## 検証
`tests/online-bot-castle-race-budget-guarded.cjs`: 固定場面で12秒以内に到達可能な前衛からの貯蓄→ドローン投入、遠すぎる攻勢部隊では従来BOTへ戻す、緊急時は衛士を出す。さらに既知6シード×両陣営×10条件×3戦術（衛士優先型/V1/V2）=360試合で勝敗・城HP・敵城ダメージ・資源・砦保持・計画数を比較。

勝敗悪化が無くても明確な改善がなければ採用せず、独立holdoutには進まない。公開mainへの変更には別途承認が必要。


## V2の360試合・結論（2026-10-18）

[実行ログ](https://github.com/8mahi8/shokoku-sensen/actions/runs/39107356052) は成功。既知6シード×両陣営×10対戦条件×衛士優先型／V1／V2＝360試合。固定シーンでV1は遠い部隊でも貯蓄を開始し、V2はその場合に通常の射手召喚へ戻ることを確認。近い先鋒ではV2も合法的に資源を貯めてドローンを召喚できた。城付近の危険には迎撃衛士で対応。

追加条件の「先鋒の城攻撃圏への理想的な到着時間が12秒以内」は、候補部隊が遠い状態での温存を抑制し、V1からの勝敗悪化1条件を防いだ。このV2は既知120条件で**衛士優先型と勝敗が完全一致**し、勝率の向上は確認できない。条件不成立の判定340回は同じ試合の連続BOT判断を含み、340独立サンプルではない。

**結論：V2も通常BOTへは採用しない。** 資源温存の判断を作れること、そして早すぎる温存が逆効果になることは実証したが、勝率改善は未実証。今後は味方がすでに敵城への攻撃を維持できるか（耐久、敵迎撃、推定攻撃持続）と、追加ドローンの攻城貢献が本当に必要かを区別する必要がある。今回の戦術に合わせて既知seedへ過剰適合しない。未使用holdoutは温存し、公開main・通常BOTは変更していない。
