# 小国戦線III｜城への最後の防衛線を考慮した砦放棄 (QA限定)

2026-10-18。前回の`fortRiskBudget`は固定局面では放棄を拒否できたが、既知120ペアで拒否0、通常の奪還型と勝敗・自城HPとも差0だった。既存の`fortTradeReclaim`は4回の工兵出撃で3回砦が戻ったものの、`concedeFort`より平均城HPが-19.5。城を守る目的と砦を取り返す目的が衝突し得る。

別のQA計測では、**砦喪失時点で城までの可視敵の直線ETAが10秒以下**の区間で、30秒観測できた56件中54件に城ダメージが確認された。ただし喪失を原因と断定できず、失う前から城が攻撃されているケースが含まれ得る。これを**予測モデルの正しさとは扱わない**。

新候補`fortLastLine`は、`fortRiskBudget`の法定4コスト待ちを基本とし、次をさらに考慮する。

- 占領中の味方砦が1個だけなら、可視敵の城接近最速ETAが24秒以内、かつ城付近に味方の防御部隊がいなければ放棄せず従来の緊急防衛へ戻す。
- 味方砦が2個以上なら、上記ETAが16秒以内・城付近を守る味方がいないときは、砦を守る方へ切り替える。前方砦が十分離れているなら資源を貯める選択肢は残す。
- 自城HPが半減している局面では追加リスクを許容しない。
- 途中で敵が接近し、城への危険が増したら資源温存を打ち切る。4枚手札・移動ルール・公開資源・ユニット性能は変更しない。
- 占領の経路が有効な場合のみ重装工兵を奪還役に選ぶ。不適合なら迎撃衛士など元の防衛へ戻す。

24/16秒という閾値は、過去の**既知訓練シードからの試行的な保守設定**であり保証はない。既知の6シード×青赤×5スタイル×2条件で、通常BOT・直前の`fortRiskBudget`・新`fortLastLine`を各120回（合計360試合）対照比較する。固定局面では「城に近い最後の砦では守る」「別の砦が味方にあり前方で余裕があるなら待機・4コスト工兵で奪還」を要求する。改善が弱ければ通常BOTへの導入と独立シード消費を見送る。

## 追加：同一局面からのエンジン直接比較

局面別の因果比較を行えるよう、localhostのQA専用`simulateFortDecision`を実装。敵の位置・城HP・手札・資源・砦の所有・開始乱数を統一し、通常BOT・`fortTradeReclaim`・`fortLastLine`の3種類をそれぞれ正規30Hzエンジンで50秒間進める。ゲームルールと標準BOTは変えない。敵には追加召喚をさせず、「目の前の局面をどう処理するか」のみを見る短期実験なので、一般対戦の勝率推定は不可。

[GitHub Actions #39061851693](https://github.com/8mahi8/shokoku-sensen/actions/runs/39061851693) 成功。既知5シード×5事前定義局面×3戦術＝**75ケース（25比較セット）**。

| --- | ---: | ---: | ---: |

特に**前方砦へ高速偵察ライダー2体が来る**ケース（各5試行）では、従来耐久・奪還型の城被ダメージ平均672に対し、通常BOT・最後の防衛線型は各1288。通常BOTより砦保持時間が短くても、城に対する防衛は良くなる実例があった。他方、最後の砦に遅い工兵2体が来たケースでは、いずれも自城ダメージ0、通常BOTは保持時間が長いが、耐久・奪還型は失った砦の奪回5/5。**砦保持と城被害の最適化方向が一致しない**。

この小さな人工局面群に統計的一般性はない。追加召喚なし、味方手札の固定、敵BOTの本当の意思決定なし、地形と初動のみを統一した局面。とくに50秒中の新たな敵攻撃は再現できない。

### 次段階の意思決定モデル

「砦から城までの距離が近いから必ず守る」も「取られたら必ず工兵で奪い返す」も不正解。**いま2コストで防衛しても突破される確率、4コストまで待ったときの敵掃討と反攻の可能性、手札のカードが実際に砦へ進む時間**を別々に評価する必要がある。前方の防衛線が崩れそうなときこそ、いったん下がって質の高い迎撃を整えることに価値がある場合もある。

次の候補は固定ルールの秒数閾値を変えるのではなく、「即時投入がその局面で何を防げるか」を見る。既知学習条件の都合の良い選び直しは行わず、独立holdoutは残す。
