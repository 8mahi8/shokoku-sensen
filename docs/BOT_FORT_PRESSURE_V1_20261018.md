# 小国戦線III｜奪還か攻勢か：判断開始時点の見える情報を検証

2026-10-18。develop QA専用。公開main・通常BOT・ユニット性能は不変更。

## 問いと問題
前回は各政策22エピソード中14エピソードで、砦の再確保より先に自軍が勝った。ただしこれは**事後ラベル**であり、開始時点で攻勢重視が最善だった証拠ではない。事後の勝者をBOTに使わせず、計画開始時点の信号を独立に記録する。

## 記録する観測信号
城HP差（自城－敵城）、味方と敵の現存ユニット数、敵城壁面から水平300px以内の非guard味方数、自城壁面から300px以内の敵ユニット数、各城壁面までの両軍ユニット最短水平距離。いずれもBOTが実際に観測可能なゲーム内公開情報であり、将来の増援・後の勝敗は含まない。300pxは分類のための暫定測定幅で、政策のしきい値ではない。

## 評価
既存の30Hzフルゲーム 6既知シード×2陣営×10対戦条件＝120条件、通常・工兵優先・衛士優先の360試合を再実行。QA `tests/online-bot-fort-horizon.cjs` が `qa-bot-trade-horizon/pressure-audit.json` を出力する。計画開始時に凍結した特徴と、90秒以内の先着イベント（奪還/終局）を事後照合する。対応する両候補の同一局面を別々の独立標本とは数えない。

分析コードでは、「砦を最初に失ったのが90秒より後」を90秒までの未奪還に誤分類しない境界テストも追加。対象砦が最後まで失われない場合は再確保不要。

**採用はしない**：本変更は観測だけで、勝敗改善・最適判断はまだ実証していない。次の戦術実験は、事前に評価式と比較基準を決め、既知シードで調整しすぎず、holdoutは最終確認時まで保存する。


## 初回の360試合で確認したこと

[Actions #39104110452](https://github.com/8mahi8/shokoku-sensen/actions/runs/39104110452) は SUCCESS（既知6シード、120対照条件 × 3政策 = 360試合）。戦術別22計画が記録され、22組は開始局面の対応が取れている。工兵優先と迎撃衛士優先で下記の**開始時点の特徴量と終局の分類はすべて同じ**なので、44独立事例と解釈しない。

| 最初のイベント | 件数（各政策） | 敵城壁面±300pxに非guard味方ユニットが存在 | 開始時の自城HP優位 |
| --- | ---: | ---: | ---: |
| 再確保前に自軍勝利 | 14 | 11 | 8 |
| 再確保前に自軍敗北 | 1 | 0 | 0 |
| 再確保達成 | 2 | 0 | 0 |
| 90秒経っても未再確保 | 2 | 0 | 0 |

22計画のうち、開始時に敵城近くに非guard味方戦力がいたのは11件。その11件の事後ラベルはいずれも「奪還前に自軍勝利」だった。ただし、勝利全14件のうち**3件はこの圧力条件を満たさない**。HP差の平均は勝利群で+273.714、他の結果群は平均0。自城壁面300px内に敵戦力がいたのは計1件（これも勝利群）。

**制限と解釈:** ここで用いた300pxはQAの観測距離であり、事後の11/11をもって実戦で高精度と称してはいけない。攻勢戦力が城に近いとそもそも勝ちやすいだけの可能性があり、砦を放置したことの因果効果ではない。また小さく依存のある既知局面、独立holdout未使用、相手戦術5種類の偏りもある。今後もし攻勢優先のQA候補を作るなら、**城HP/敵の進撃/残時間を併せて、受け入れ基準と比較を先に固定**し、勝敗・城HP・砦所有時間・資源効率のトレードオフを検証すること。

当該変更で通常BOTが選ぶカードは一切変更されない。iPad/埋め込みHTMLもゲームJSを完全同期済み。
