# 小国戦線III｜砦奪還の90秒競合イベントQA（2026-10-18）

develop専用。公開main・通常BOT・対戦ルールの変更なし。

## 研究目的
従来の30/60/90秒平均は各時点まで試合が継続した局面に限られ、早期敗北などを比較から落としていた。新QAは全計画を「砦保持」「奪還」「試合終了」の排他的な結末に分類する。観測の完走数だけで再確保率を判断しない。

## 計測を拡張
- `waitForFourSeconds`：現在の資源から4コスト到達までの見積。
- `engineerTravelFloorSeconds`：召喚予定位置から砦への最短直線移動（工兵移動速度16、攻撃可能距離58pxまで）。
- `engineerCaptureFloorSeconds`：砦HP12、工兵占領2、攻撃間隔1.4秒。初撃即時・追加5撃までの理論最小7秒。
- `engineerRecaptureFloorSeconds`：資源待ち＋理論最短移動＋占領攻撃時間。敵との戦闘、砦の所有変化、妨害、増援は含まないため、**成功予測ではなく楽観的な下限**。
- `timeLeftAtPlanSeconds`：制限時間300秒までの残り。
- `visibleHostileCastleEtaSeconds`：現在見えている地上敵の直線的な城到達ETA。敵なしはnull。実際の被害時刻ではない。

## 分類
全計画について90秒以内の最初の砦喪失・再占領と試合終了を照合。
1. 砦が落ちる前に試合終了
2. 90秒間砦が一度も落ちない
3. 90秒以内かつ試合終了前に一度以上奪還
4. 90秒経過でも奪還していない
5. 奪還前に自軍勝利
6. 奪還前に自軍敗北
7. 奪還前に引き分け

「初回奪還」と「90秒時点で保持」は異なる。対応する計画は同じシード・陣営・相手条件・砦、開始時刻差0.25秒以内でのみペア化する。独立した44標本でもランダム化実験でもない。

## 再現
`node tests/online-bot-fort-horizon.cjs`：同じ30Hzゲームエンジン・合法的な敵増援・既知6シード、360試合。既存テストと新しい分類用の簡易境界テストを含む。成果物 `qa-bot-trade-horizon/recapture-race.json`。

**結論の取り扱い**：今の変更は計測だけ。理論的最短奪還時間が残り試合時間を下回っても、妨害で奪還できない場合がある。未使用holdoutを消費せず、候補戦術の公開採用判断は行わない。


## 検証結果（Actions #39102397542、実行成功）

[実行ログ](https://github.com/8mahi8/shokoku-sensen/actions/runs/39102397542)。
既知6シード×陣営2×対戦条件10＝120対照条件、通常/工兵/衛士の計360全長試合を完走。計画22件/戦術、対応計画22ペア。下表は**戦術別22件**を分母にした90秒競合イベント分類であり、合計44独立計画ではない。

| 90秒までの最初の結末 | 工兵優先 | 衛士優先 |
| --- | ---: | ---: |
| 砦が落ちる前に試合終了 | 3 | 3 |
| 90秒まで砦未喪失 | 0 | 0 |
| 90秒以内に再確保 | 2 | 2 |
| 90秒経っても未再確保 | 2 | 2 |
| 再確保前に自軍勝利 | 14 | 14 |
| 再確保前に自軍敗北 | 1 | 1 |
| 再確保前に引き分け | 0 | 0 |

対応計画のイベント分類差は**0/22**。既知120対照の最終勝敗差も以前と同じく0。単純な「90秒まで再確保できなかった計画」の大部分は実際には再確保より先に**試合自体が自軍勝利で終わっていた**。よって「砦が戻らなかった」を単純な戦術失敗と呼べない。

工兵を温存対象に選んだ計画は工兵優先型6件、衛士優先型3件。楽観的な工兵奪還時間下限の平均はそれぞれ約13.43秒、約12.31秒で、両群すべて理論上は90秒と試合残り時間に収まる。しかし実観測で60秒以内の再確保はゼロ。**理論値は到達の証明にならず**、交戦、占領対象の変化、追加召喚や工兵以外のユニットが再確保した可能性を含めて解釈する必要がある。

「自軍勝利の見込みが高く砦奪還を急ぐ必要がない」と判断できるかが次の検証候補。ただしこれは**勝利後の事後情報を使う最適化**にしてはいけない。BOTがその時点で見えている城HP、攻勢、残り時間、部隊、資源のみで予測し、未使用holdoutで確認するまで通常BOTには適用しない。
