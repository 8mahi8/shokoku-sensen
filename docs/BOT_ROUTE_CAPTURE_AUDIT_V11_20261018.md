## 対象一致を確かめる限定補正 `captureRouteOpportunity`
`online-game.js`・`online-embed.html`・`online-ipad.html` にQA専用variantを追加。従来のBOTの優先順位は維持し、`workers`が足りていると判断したときだけ次を試す：

1. 実際の`getFort(u)`で、その未確保砦に割り当てられている味方占領役を再カウント。
2. こちらが不足なら、**現時点で購入可能な**偵察ライダー／工兵を確認。
3. その召喚場所からの`getFort(probe)`が**目標砦と一致**する場合に限り正規召喚。敵守備兵がいる場合には脆い偵察ライダーを無理に出さない。
4. 進軍路・ユニット性能・初期手札・コストを変更せず、通常方策にフォールバック。

これは「手前の基地を常に目標とする」という既知の弱い仮説と区別する。

## 結論
- `captureRouteOpportunity` は通常BOTに**不採用**。見かけ上104回の不一致からそのまま「104回弱い行動をしている」と結論しない。
- 前線を飛び越して奥の砦を狙う戦術を一律に除去しない。移動規則の変更は禁止のまま。
- 新たなしきい値調整や既知シードの勝率最適化を一旦停止。より実際の行動に結びつく**支出の機会費用・高頻度の局面**を次の観測候補とする。
