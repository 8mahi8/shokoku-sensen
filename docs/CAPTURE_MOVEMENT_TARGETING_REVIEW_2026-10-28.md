# 小国戦線III｜占領型が遠い砦に吸い寄せられる原因・移動/追撃ルール設計 v0.1

作成：2026-10-28 JST。**ユーザーの学校iPad実機フィードバックに基づく設計レビューであり、AIの本体ロジックは変更していない。**
固定学校基準：`stable/school-ipad-20261028-99a0d1d` (`99a0d1d0cc18a987aefe0ab99dc1f7993160fe25`)。`main`／Google Sites／Firebase／Drive配布／安定ブランチは保護対象。

## 今回確認した方針
- 攻撃型は移動で大きく後退しないが、射程内の**背後**の敵も攻撃可能（本人もC案でよいと回答）。戦闘の攻撃先再選択はB案、つまり**攻撃直前にその時点の最寄り有効対象から選ぶ**（なお実装は未着手）。
- 8つのユニット基本項目の一つとして`vision`（敵兵の索敵範囲）を保持。射程`range`から自動計算しない。
- ユーザーは**占領型がかなり遠い砦までわざわざ向かうため、置いた場所に応じた狙いの動きができない**と実機体験を報告した。

## 安定版における原因（online-game.js の getFort／unitStep）
- `CLASSES.scout.vision=115`、`CLASSES.engineer.vision=120`。
- **敵兵索敵 `nearbyEnemy()` では `vision` を使用するが、砦検出 `getFort()` では `vision` を参照しない**。
- 砦候補は①味方所有でない、②そのユニットの前方から後方42以内（`direction*(fort.x-unit.x)>=-42`）、③`abs(fort.y-unit.y)<220`。**X方向／直線距離の上限がない**。
- 占領型（`behavior="capture"`）は、標準の人間対人間で候補のうち**最も前方（敵陣寄り）にある砦を優先**する。コメントにも「Human BLUE and RED troops must follow the SAME forward-targeting rule」とある。最寄り砦を狙う`nearestCapture`は**QA BOT向けの実験モード**で、標準人間プレイには適用されていない。
- `unitStep()` の占領型は`fort`が存在する限り、目の前の敵に即時反撃する場合を除いて、**距離に関係なく砦へ向かう**。
- **それゆえ「敵索敵が広すぎる」ではなく「砦目標選択に最大距離がなく、最前方を優先する」という別の原因**。敵索敵`vision`を115→80などへ縮めても問題は基本的に治らない。
- 砦の初期座標は`(410,190),(633,444),(867,205)`。青初期線`x=244`、赤初期線`x=1036`。

## 固定座標での検証（実装コードから得た判定を数値で再現：実ゲーム通し試験は未実施）
すべての砦が中立で、通常の人間対人間の標準ルールとする。距離は丸めた中心間の数値。候補の前方／Y条件も反映。

| 召喚例 | 現在の選択 | 「半径300以内から最寄り」の仮ルール |
|---|---|---|
| 青 x244 y330 | **右砦まで約635** | 左砦まで約217 |
| 赤 x1036 y330 | **左砦まで約641** | 右砦まで約210 |
| 青 x244 y520 | 中央砦まで約396 | 現在位置では対象なし（敵城方向へ前進し、近づいた時点で再索敵） |
| 青 x458 y190 | 右砦まで約409 | 現在位置では対象なし（※左砦が味方所有、かつ中央砦はY差254で現行候補から除外される場合） |
| 青 x690 y330 | 右砦まで約217 | 右砦まで約217（中央砦は現在位置より後方57のため候補外） |

**数値300はQA向けの試案であり採用確定ではない**。従来の`abs(dY)<220`、前方許容42を保った仮の比較。いずれも他兵種の`vision`とは独立した占領型共通ルール。
「既存の`vision`をそのまま砦にも適用」は危険：青x244,y330→左砦約217>偵察115/工兵120となり、初期配置時に最初の砦さえ認識できない。最初の砦からYが140離れているので、水平移動だけでは視界115に入らず素通りする恐れもある。

## 提案する簡素な占領型の目標選択
1. 占領型は**配置場所からの近さ**を尊重する（砦目標に独立した短い探索距離上限を課す）。**第一候補：前方の半径約300以内の「最も近い敵/中立砦」**。
2. 対象砦は確定後、一定の条件（味方所有、候補として不適切、到達不能など）までは**保持**して、毎フレーム別砦へ引きずられないようにする。砦への目標固定と**攻撃する敵のB案再選択は別物**。
3. 砦が候補にない場合は、行動型として**敵城方向への前進**へ戻す。前進中に砦が探索圏内へ入ればそちらを目指す。
4. 敵への反撃は原則、砦への行動を放棄させないよう**至近距離の有効敵に限定**。反撃対象はB案「攻撃できる直前の最寄り」で選択。遠い敵の追跡はしない。
5. 最前方砦を常に狙う旧ルールは一部の**飛び地奇襲**に役立つが、プレイヤーの召喚位置の意図を潰すデメリットがある。前進召喚ラインや狙う砦に近い場所への配置で奇襲を成立させられるか、実機で比較する。
6. 近い砦を複数見つけたときは**最寄り**、距離差がほぼ同一なら進軍方向にある方、まだ同値なら砦ID順で固定。ランダム選択禁止。
7. 砦の探索半径は**全占領型共通のルール定数**として管理し、ユニット基本設計に9番目のパラメータを増やさない。敵索敵の`vision`は引き続きキャラごとの値。
8. 対戦は全チーム同一基準。QA BOT variantが人間の物理に混入しないこと。ゲーム本体への適用前に固定シナリオテストを用意。

| 判断 | キャラの基礎属性 | 行動型共通AI | プレイヤーによる技術 |

## 実装前の受け入れ条件
- 初期位置の左右中央・上・下、進軍ライン前後、砦中立/敵/味方所有の全ケースで目標が理解可能。
- 赤青を左右反転したテストで一貫した行動。
- 兵がすぐそばを通り過ぎた砦を不自然に無視しないか（「前方から後方42以内」制限の検証）。
- 砦の所有者が変化しても、敵が近づいても、選択が毎フレーム揺れない。
- 初期基地の飛び地取得と深い奇襲が消えすぎないか。意図する行き先を召喚位置からコントロールできるか。
- 索敵範囲と占領対象範囲を混同しない。戦闘のB案再選択と砦目標の保持は独立。
- 青赤公平性、BOT基盤互換性、学校iPadのオンライン描画/入力への悪影響なし。
