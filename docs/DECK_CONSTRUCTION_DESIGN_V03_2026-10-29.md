# 小国戦線III｜デッキ構築設計 V0.3（2026-10-29：10種類へ訂正）

> **設計のみ・実装許可なし。** 2026-10-29の本人の訂正により、V0.1/V0.2の「基本歩兵＋8枚（8種類）」を**撤回**する。本書の最新合意が優先する。学校公開版、main、stable、Firebase Rules、既存Drive、ゲーム本体コードは変更しない。

## 1. 確定したルール

1. **基本歩兵はデッキとは別の常設カード**。選択数に含めない。いつでも従来ルール内で召喚可能。
2. **デッキに採用するのは異なるカード10種類**。同一カードIDの複数採用は禁止。1種類は高々1枠。空欄のまま試合を始めない。
3. 戦闘中の**手札は現行の4枚**、基本歩兵の常設枠を加え、操作表示は計5枠という方向を維持する。
4. **ユニットもスペルも編成候補**。編成時の性能上書きや強化は行わない。カード固有の使用回数・消費コスト、3行動型／ターゲット優先度は既存のまま。
5. デッキ候補の供給元は既存の `CATALOG={...CLASSES,...SPELLS}` に基づき、`infantry`を除く「編成可能」カード集合。新キャラ追加時に共通戦闘AIとは独立して編成候補として扱えることを目標とする。

**未決のままの設計提案**：試合開始時のシャッフル、スペルの構成割合自由、8/8ではなく10/10からの2タップ交換操作、保存仕様、再戦編集、対戦相手の編成非表示、BOT対応の段階分離。以前のV0.2にある重複禁止の「未承認」という記述は**本版で確定に更新**する。

## 2. 最も重要な設計上の帰結

2026-10-29現在の実装の編成候補は**ちょうど10種類**：

- ユニット8種：`scout`、`engineer`、`archer`、`sentinel`、`suppress`、`guardian`、`drone`、`tank`。
- スペル2種：`barrage`、`ward`。
- 基本歩兵 `infantry` は、この候補10種類に含まれない常設カード。

したがって**現在の候補10種類から異なる10種類を選ぶと、合法な編成は一通りしかない**。今のうちにゲームへデッキ編集UIを載せても、カードの入替はできない。これはルールの矛盾ではなく、**自由編成の意味が出るのは11種類目以降の候補が登場してから**ということ。12種類なら66通り、15種類なら3003通り（選択順は区別しない）。

本人に無断で新キャラや新スペルを増やさない。新候補の企画・追加は別途合意する。10種類しかない状態では現行固定10種類を正規の初期デッキとして保持できるため、従来ゲームの再現性がむしろ高い。

## 3. 10種類前提のカード循環・UI案

- 従来 `DECK_IDS` 固定10種類、`HAND_SIZE=4`、`S.hand[team]`／`S.queue[team]`、`advanceHand`、`S.left` と完全整合する設計を基本にする。
- 10種類を試合開始時に1度シャッフルし、手札4種類／待機列6種類として開始。使用時は残回数があれば列末尾に戻り、使い切ったら退場。無条件に毎回10種類を引き直さない。
- 新カードが追加された時のデッキ編集UI案：**「選択中10/10」**、採用10種類、残り候補から「入替するカード」を選択し、交代対象をタップする2タップ方式。ドラッグ不要。
- 全10種類しかない初期状態では選択中10/10の表示、能力やコストの参照、将来の候補拡張に備えた外見のみとする。無意味な「11枚目のカード選択」や空スロット表示を強制しない。
- 構築後も4枚の手札と基本歩兵の操作は変えない。将来カード数が増えても、**選択枚数10・手札4は固定**という構造を基本とする。

## 4. オンラインでの確定方法（詳細はV0.2 §4〜7参照、枚数のみ変更）

- 入場／再戦時に各自の10種類の下書きを持つ。準備完了時に本人の10種類のカードID、参加者ID、ラウンド、版数を一緒に確認して編成固定。
- ホストは開始前に双方の**ちょうど10個・すべて一意・歩兵なし・存在するカードID**という条件を検証。準備情報とデッキを同じ確定手順でロックし、対戦中の書き換えが `S.hand`／`S.queue`へ混入しないようにする。
- 既存 `online-net.js` は `players/ready` と `meta/status`が別管理で、競合に配慮が必要。Firebaseのトランザクション範囲や旧クライアント拒否、接続回復は**実装前に具体的な手順・テスト仕様を定義**する。
- 毎回ネットワークでデッキ全体を送り直す必要はなく、ゲームの高頻度同期は既存の手札・待機列・残使用回数を使用する。
- Google Sitesに埋め込んだSafariでは保存領域が使えない可能性がある。必須ログイン、保存権限、永続ストレージなしで試合を始められること。
- 初版ではソロBOTの固定10種類挙動を維持。友達との1vs1のデッキ確定とBOTの新しい編成戦略を同時開発しない。
