# 小国戦線III｜学校iPadの描画モードを既存診断に追加（2026-10-28）

## 根拠
- 学校での本人の実測：ゲストは普段快適だが時々軽いカクつきが残る。一方Linux headless WebKit録画ではホストもゲストも一律4〜10FPSになりやすく、実iPadの滑らかさを再現しない。
- [背景可視範囲 A/B](TERRAIN_VIEWPORT_AB_2026-10-28.md)は8条件すべてピクセル差0、描画コスト改善はほぼ無し。不採用。過去にはCanvas/HUDオフ試験も複数回済み。根拠なしの画質削減は避ける。
- `online-game.js`の実体では、ゲストが低FPSを検知すると`guestLowPower`で約30fps上限の描画間引き、`lowFpsCrowdedSprites`で混戦時の兵士ポーズキャッシュに切り替わることがある。後者はゲスト以外でも有効になり得る。学校の実機でこれらが発動しているかは**未確定**。
  
## この改修
- ゲームタイトルを3回タップすると出る**既存の端末内パネル**に「描画モード」「Canvas DPR」「兵士キャッシュ中／通常」を表示する。
- 新しい診断ボタンは追加しない。普段のプレイでは非表示。表示条件やキャッシュ切替閾値、Firebase通信、ゲームルール、フレーム描画頻度は**一切変更しない**。
- 表示する値は**この端末のJS内部状態を読むだけ**。ログ保存・自動アップロード・研究データ・Firebase追加ノードなし。ゲスト側の180ms以上フレームギャップとSDK受信seqの既存表示も維持。
- 学校端末で任意にパネルを確認する際、`描画モード ゲスト約30FPS上限`と表示されても必ずしも現時点で30FPS出ている意味ではない。緊急時の表示上限状態を示すだけ。実機の表示が`通常`なら描画制限が原因だとは言えない。
- まず smoke・iPad UI・ゲストラボ・実Firebase対戦の回帰を確認してから正式な開発候補とする。Linux WebKit FPSの改善を主張しない。

## 保護
- Google Sites公開版 / `main` / Firebase本番ルール変更なし。Google Drive保存は本人から明示指示があるときだけ。
