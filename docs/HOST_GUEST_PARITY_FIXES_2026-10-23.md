# 小国戦線III｜ホスト・ゲスト差分修正（2026-10-23）

## 版の取り決め

**Google Sites版＝ユーザーが実際に貼って遊んでいる「再戦修正版」**。本変更は GitHub の `perf/online-guest-snapshot-diagnostics-20261020` **開発ブランチ限定**。既存のGoogle Sites版、main、Firebaseの公開ルール・データは変更しない。学校iPad実機の採用判断は未実施。

## 修正点

1. **占領部隊AIの公平性**：`getFort(u)`で通常／難しいというBOT設定が人間ゲスト赤軍の進軍先にだけ混入していたので削除。両軍とも自軍前進方向でより奥の候補前哨基地を優先する、元々の青軍と同じ方針へ統一。BOTの召喚意思決定コードは変更しないが、BOTの赤軍占領部隊も同じ進軍方針になる。**BOT戦術が変わる可能性**があり、必要なら専用BOT戦略で調整する（人間と兵士の物理挙動は共通のまま）。
2. **ゲストのカード選択**：ゲストが非基本カードの送信に成功したらホストと同様にカード選択を解除する。基本歩兵は選択を維持。状態スナップショットで選択済みカードがもう自分の手札にないか残数0なら解除する。これにより使用済みカードのまま別の召喚場所をタップする事象を防ぐ。**ホスト側のカード処理・コスト・手札回転は変更なし**。
3. **通信切断時の命令**：`sendCommand`は接続・座席・命令妥当性の条件を満たした場合にのみtrue（「ローカル送信開始」を意味しホスト成功ではない）を返す。それ以外はfalse、ゲストは「通信が切れています」などの誤認防止表示。
4. **ゲスト失敗通知**：ホストの拒否通知に現在のラウンド番号を付け、ゲストは`seq<=commandSeq`かつ未処理seqである通知を受け取る。従来の「最新命令のseq以外は表示しない」を緩和。ロビー内の隠れた`netStatus`だけでなく、対戦中の`announcement`にも表示。試合間で直前の通知が混ざらないようseqを初期化する。**同一feedbackノードの上書き構造であるため、複数同時拒否が必ず全件届くわけではない**。命令の結果を先読みで確定扱いしない。
5. **自軍／敵軍表示**：青軍固定の前哨基地・城壁・召喚ラインのラベルを`ME()`基準で両軍正しく表示。陣営の色・座標・当たり判定は変更なし。召喚失敗時の「青い召喚範囲」という誤説明も自軍基準へ変更。

## 変更していないところ

- エネルギー補間（前のコミット）、実際の`S.energy`、カード使用可能条件、兵のHP/攻撃力、勝敗判定、両端末でフル戦闘計算する仕組み。
- 本番Firebaseへの新データ記録やマッチ履歴、マリガン機能（アイデア段階）。
- ホストゲーム時計をCPU/FPSから独立させる大改造（実機性能・通信を計測してから判断）。

## 回帰試験

`tests/online-smoke.cjs` に、現行の`getFort()`実関数で青・赤、難易度3種、部隊2種の目標座標比較を追加。ゲスト`playCard()`実コードで非常設カードの解除、歩兵選択維持、送信不可時の不変を検証。シリアル版と埋め込み2種、ゲストラボ版を整合させた。オンラインの実Firebase / WebKitチェックはGitHub Actionsで実施し、実iPadでは未確認。

## 既知の未修正リスク

- 双方でゲーム時間を処理する方式への変更は必要性が未確定。
- 次＋1のゲージは受信間だけ画面予測し、実コスト判定は正式データに基づく。実iPadでのFPSや受信Hz改善は未実証。
- ホスト側で出る「砦占領」などの情報通知がゲストにも全部同じ形で出るわけではない。バランスを崩さない範囲の次フェーズ候補。
