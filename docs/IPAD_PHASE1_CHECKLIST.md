# 小国戦線III｜学校iPad Phase 1 実機確認（最小手順）

目的：ヘッドレスWebKitのFPSを実iPadの数値と混同せず、Google Sitesの**貼り付け版**で操作・通信・描画を分けて確認する。**PR #22は未公開**なので、公開用HTMLを正式に更新してからの最終検証が必要。mainや既存Google Sitesをこの資料のために変更しない。

## 2人で確認（音なし・横向き・1vs1）

1. 同じGoogle Sitesページをホスト（青）とゲスト（赤）で開く。ルーム番号を入力して1試合開始。
2. 両端末でゲームの**タイトルを素早く3回タップ**して「通信・描画の診断」を開く。測定値は**端末内のみ**でFirebaseには送られない。見えなければタップ間隔を短くする。
3. ゲストの診断画面で「描画 FPS」と「通信 guest 更新/秒」「SDK受信 seq」を見る。開始後15秒、交戦中（通常兵約8～20体）、大型キャラ／砲撃が見えるときにチェック。ホストは「描画 FPS」「配信 host seq」を見る。
4. どちらかの画面がカクついたら、操作が遅いのか、**兵士・弾の見た目だけ遅れる**のかを区別。診断は開いたまま再戦できる。対戦中の切断試験は、友達と合意の上で実施する。
5. 同じルームで2～3試合再戦し、再戦時の固まり・カードの操作不能・両チームのHP同期がないか確認。

判断のヒント：**FPSが低いのに更新/秒が普通**なら描画/ブラウザ側が候補。**FPSが普通なのに更新/秒が落ちる**なら通信／受信／適用が候補。両方悪ければ両経路の調査が必要。これは仮説であり、iPad実機・Google Sitesの制限に依存する。

## 開発側の基準

- CIでの実Firebase7試合とWebKit/Chromium8～20体は既存テストで成功。ただしCIの実戦WebKitは低FPSで、実iPadと同一ではない。
- PR #22の最適化はGoogle Sitesに貼り替えるまでは実際の公開ページへ反映されない。
- 本番へ出すには、開発側で回帰テスト・目視レビュー後、ユーザーが**単体HTML全文をGoogle Sitesの埋め込みコードに貼り付ける**。新しい機能やバランス変更は不要。
- 学校の個人情報、友達の名前、ルーム番号などの共有は不要。診断表示の数字と起こった現象だけでよい。
