## 2. 理論総DPS（全員が生存して同時に攻撃できる理想条件のみ）

- 現行：親`15/1.9=7.89`＋通常8×`14/1.5=9.33`＝**82.56**。
- 前回の「8体とも軽強化」案：親7.89＋8×`18/1.5=12`＝**103.89**。
- 今回案：親7.89＋通常7×12＋最終型`35/1.5=23.33`＝**115.23**。
- 現行比の理想上限約+39.6%、前回の一律案比約+10.9%。**この値は実戦の期待DPSや勝率ではない**。子は時間差生成、攻撃できる時間・射程、相手の範囲攻撃、死亡に左右され、常に8体生存しているとは限らない。
- 生成6秒後（3体とも生存）の理論上限：現行35.89→**43.89**。最終型による追加分は31秒以降なので、早期の弱さは通常子機の軽強化によって補う。

## 4. 良い点・危険性・実装の最小経路

- 良い点：ユーザーの「生き残っても弱い」という体感に対して、通常子機を軽く強化＋生存報酬の最終型を追加する二段階の改善。生成を無限化しない。最後の1体に視認可能な特別感が出る。
- 対抗策：無軽減の新威力180範囲砲撃で普通の子機HP105は即撃破、最終型HP220は**40残る**。ただし小型機は引き続き飛行敵へ反撃不能・砦占領不可、親が倒れると以降の新規子生成なし。
- 懸念：1コスト単位での効率は**親+子の生存率**で大幅に変動し、同じ召喚師を2枚出すと2体の最終型が出る可能性。これは上限2回カードの既存仕様内。通常+最終型の両方を過剰強化しないよう、まず仮値のまま実戦評価する。
- 実装方式の候補：既存`small_machine`をHP105/攻撃18へ更新。**内部専用の`small_machine_elite`を追加**し、親の`summonCount===7`の時だけ最終型の子を生む。既存の共通移動/対象AI/攻撃/通信スナップショットをそのまま利用し、新カードとしてデッキに表示させない。最終型だけ明確に異なるシルエット/色・召喚演出を用意する。キャラ追加時のアート定義・効果・HPバー整合をテスト。
- ユーザーが数値を認めるまでは本体コードに手を加えない。まずこの案を提示し、承認後に既存テストとオンライン実画面・学校iPad Safariを検証する。学校Google Sites稼働HTML、main/stable、Firebase Security Rulesは今回変更しない。
