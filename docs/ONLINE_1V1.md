## 学校iPadでの公開方法（BRAWLと同じ方式）
1. **PC**で [online-embed.html（Raw表示）](https://raw.githubusercontent.com/8mahi8/shokoku-sensen/main/online-embed.html) を開く。
2. HTMLの全文をコピー。
3. Google Sites のオンライン対戦用ページで「挿入 → 埋め込む → 埋め込みコード」に貼り付ける。
4. 埋め込みの縦幅を十分に広くし、公開する。なるべく横向きのiPadで遊ぶ。
5. 片方が「ルームを作成」、他方が5桁番号で「ルームに参加」。2人とも「準備完了」を押して、ホストが「対戦スタート」。
6. 準備フェーズ10秒、制限時間5分。両者同じカード、資源と部隊制限。ホスト青軍／ゲスト赤軍。Google Sites上ではPCから埋め込むだけでよく、Driveへの転送は不要。

**注意**: GitHub Pagesのドメインが学校の端末でブロックされる場合は Google Sites 埋め込み版を使う。Google Sitesのiframeのネットワーク制限やFirebase SDKの読み込み制限がある場合、個々の学校の環境で動作確認が必要です。

## 学校のHTMLでHP・攻撃力だけ調整（2026-10-21）

- 開発PR #22のGoogle Sites用 `online-ipad.html`（または `online-embed.html`）の**最初の約30行**に、`★ 学校でキャラ調整する場所 ★` と表示された `window.SHOKOKU_UNIT_STATS` 一覧を追加。
- 全9ユニットの `hp`（HP）と `damage`（基礎攻撃力）の数字のみ変更可。例：`infantry: { hp: 105, damage: 15 }` → `infantry: { hp: 150, damage: 25 }`。キャラ名、コロン、カンマ、括弧を消さない。
- HPは1〜99999、攻撃力は0〜99999の**整数**のみ採用。不正値は元の設定のまま。魔法（ファイヤー）、城、砦、コスト、射程、速度、戦闘判定は対象外。
- 値はゲームの `CLASSES` に起動時1回反映され、召喚時のHP・実際の攻撃処理が参照する。データ一覧を画面だけに表示する機能ではない。普通の `online.html` では既存の値を維持する。
- 変更後のHTML全文をGoogle Sitesへ貼り直して再公開し、**対戦する両端末で同じ最新版ページを開き直す**。古い埋め込みHTMLは自動では更新されない。オンライン対戦ではホストが戦闘計算を担当するため、別バージョン同士の混在は避ける。
- 実装・初期値・インラインJS/シミュレーションの検証： [Online 1v1 smoke #39499222485](https://github.com/8mahi8/shokoku-sensen/actions/runs/39499222485)。18〜20体での画面テスト、オンライン実Firebase回帰は先行CIで合格。学校iPadでの今回の**手動数値変更後**の対戦は未検証。

## 友達向けの対戦データ（2026-10-21 時点）

- **現在はローカル記録だけ**。対戦したホスト端末内に匿名のカード使用・局面・勝敗が最大8試合分保存され、必要なときだけJSONを書き出せる。君が不参加の試合のデータを、君の端末やChatGPTへ自動転送する仕組みはない。
- 以前試作したFirebaseへの専用クラウド送信・別チェック欄は、友達だけの遊びには複雑すぎるため**開発版の実行コードから撤去**。将来の参考資料は [RESEARCH_CLOUD.md](./RESEARCH_CLOUD.md) に凍結保存。本番設定・課金を変更していない。
- 将来必要になれば、現状すでにFirebaseへ送信している勝敗・対戦状態を活かした**小さな統計保存**から検討する。RTDB権限・読み取り可否を確認するまでは新しい自動送信先を作らない。

## 通信方式
- Firebase Realtime Database: 既存BRAWLの動作実績がある同じプロジェクト（DB URLは online-net.js 内に設定済み）。
- ルーム領域は **/shokokuRooms1v1/{roomCode}** に限定。BRAWLの `/rooms` と `/rooms2v2` を使用・編集しない。
- ルーム作成はRTDBトランザクション、重複部屋を避ける。入室は2人限定、後から参加した人が赤軍。
- それぞれの端末で実時間を独立計算しない。**ホストだけが移動/ダメージ/占領/資源/勝敗を計算し、ゲストはスナップショットを描画する**。
- ゲストはカード・座標の操作のみ送信。ホストが `canPay` / `validTarget` / `playCard` を使って消費コスト、手札、召喚ラインなどを判定する。
- ホストは約180msおきに同期。ゲスト側のユニット描画は17０msで画面上だけ補間。勝敗は結果レコードから確定する。
- FirebaseのJSONがInfinityを格納できないため、無制限歩兵の残数は転送時だけ十分大きな整数へ正規化。権威側の実コスト/ルールは不変。
- 自動ポーズではなくオンライン対戦は速度固定。画面を閉じた場合、ホストが切断したら試合は進まない。プレイヤーに表示される接続状態を確認。
- 新しいルームコードは公開情報。DBは認証/専用サーバによる本格的な不正防止ではないため、身内対戦用として扱う。名前や連絡先などの個人情報を書き込まない。

## Firebaseの権限
このコードは既存のFirebase RTDBを使用するが、`/shokokuRooms1v1` の読書きルールが無ければ **PERMISSION_DENIED** が出る。既存BRAWL用のルールは変更せず、管理者としてFirebaseコンソールで**必要なパスだけ**アクセスルールを設定する必要がある。匿名の一般アクセスを広範囲に開くことは推奨しない。権限ルールが未設定でもUIは表示されるが、ルームを作ることはできない。

## 2026-10-14 通信安定化と再戦
- 同じ番号での再戦に対応。試合終了後にホストが「同じルームで再戦」を押すと、ラウンド番号を更新し、両者の準備状態、旧コマンド、スナップショット、結果を初期化する。ゲストはロビーに自動復帰。
- 操作コマンドと状態スナップショットを `meta.round` で検証し、別ラウンドの遅延パケットを無視。
- Firebase再接続時に本人の座席を確認して `onDisconnect` を再登録。対戦中に相手が切れた場合は画面上で警告。
- ホスト不在・期限切れ部屋への参加を拒否。24時間経過して双方オフラインのルームコードのみ再利用する。
- 終了時は `room.update` で最終戦場・結果・終了状態を一括反映。

### 2026-10-14 iPad対戦フィードバック（v4.3 UI/通信表示改善）
- 学校iPadで起動できたとの実機報告あり。ただしゲスト側のキャラがカクつき、カード絵が縦横に潰れるという報告があり、このバージョンで対策。
- v4.2系オンライン旧実装では手札・山札が `DECK_IDS` の固定順だった。現在は**ラウンド開始時に Fisher–Yates で1回シャッフル**。青軍と赤軍には同じランダム山札を割り当て、公平性を維持。1回の山札内で引き切る順はその試合中固定（カード使用時は従来どおり山札末尾へ循環）。
- ゲストは、各ユニットIDごとに描画座標を保持して毎フレーム補間し、受信間隔の短期予測を最大170msまで実施。権威位置・HP・コスト・占領は変更しない。遅延パケット受信時にアニメーション時計が逆戻りしないよう調整。
- Retina iPad / タッチタブレットでは Canvas の DPR を最大1.45へ低減。描画負荷のみ改善、戦闘距離は変更なし。カード画像は `object-fit: contain` で縦横比維持。画面サイズでフッター高さ、カードサイズ、文字サイズ、ボタン余白を調整。

## BOT練習・2端末BOTテスト（2026-10-14）

### ルームが作れない場合：オフライン BOT 対戦
1. `online.html` / `online-ipad.html` の初期画面で「**通信不要｜BOTと練習する**」を選ぶ。
2. 青軍を自分で操作し、赤軍を従来の戦術BOTが担当。Firebaseの接続・ルーム作成・認証は不要（キャラクター描画のローカルスクリプトは通常通り読み込む）。
3. 開戦準備は10秒。赤軍BOTは準備中に1回初期配置し、開戦後はデッキ、費用、手札、配置範囲を守って行動する。
4. 終了時は「BOTと再戦」で同じページ内の新しい対戦を開始。「新しいルームで遊ぶ」で初期ルーム選択に戻る。
5. 難易度はオフラインの試合終了画面から「練習／ふつう／むずかしい」を選び、次の対戦に適用できる。

### 2端末オンラインテスト：参加端末をBOTに
1. 端末Aでオンラインルームを作成。端末Bで5桁の番号を入力してゲスト参加。
2. **端末B側だけ**に表示される「この参加端末をBOT操作」を押すとBOTがONになり、自動で準備完了も送る。
3. 端末Aも準備完了し、ホストが開始。青軍を端末Aの人間が担当、赤軍は端末BのBOTが操作する。
4. BOTは端末Bから普通の召喚コマンドを送り、ホスト端末の通常チェック（資源、デッキ、配置範囲）を通す。**ホストシミュレーションは引き続き端末Aが担当**。
5. 対戦中も右上「BOT操作 ON｜手動へ」を押して手動へ戻せる。もう一度押すとBOTへ戻る。端末Bを閉じると通常の参加端末と同様に通信が止まる。

BOT機能は`online-game.js`既存の戦術BOTを共有し、BOT v4.2の`index.html`/`v3.js`は編集していない。ランダムデッキは試合開始時に青赤対称に配布する。

テスト：`tests/online-smoke.cjs`、`tests/online-sim.cjs`、`tests/online-browser-live.cjs`（実FirebaseゲストBOTと手動復帰）、`tests/online-offline-bot.cjs`（Firebase SDK遮断状態のソロ起動・BOT戦・再戦）、`tests/online-ipad-ui.cjs`。
