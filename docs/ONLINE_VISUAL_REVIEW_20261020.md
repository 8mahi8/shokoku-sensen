# 小国戦線III｜実画面を見てレビューする運用（2026-10-20）

## なぜ必要か

スモークテスト合格・対戦同期成功・通信FPSの数値が揃っていても「人間の目に自然なゲーム」にはならない。従来の `online-ipad-ui.cjs` は、メニューをCSSで隠した**戦闘開始前**の静止画が中心で、兵士・弾・衝突・集団戦を目視レビューできていなかった。

## 新しい二層の目視QA

1. **ローカル描画の実際の戦闘** `tests/online-battle-visual-review.cjs`：iPad相当 WebKit と Google Sites相当のコンパクト Chromium。BOTとの通常戦闘、時間差画像、移動する兵士130体の負荷戦闘を実際のゲームループで描画。WebKit動画・10枚のスクリーンショットを成果物に保存。ゲーム側にFPS計測のための補正を加えない
2. **実Firebaseのゲスト画面** `tests/online-browser-live.cjs`：Chromiumホスト+WebKitゲストの本当のFirebase一時ルームで、ゲスト操作・戦闘・通信停止からの復旧・3回再戦を録画。動画と時間差スクリーンショットを成果物に保存。実Firebaseのテストルームは最後に削除する

## AI担当が実際の成果物を開いて評価する項目

- 兵士の動き：急なワープ、テレポート、カクカク、補間での残像
- 弾・範囲攻撃：攻撃が出た時刻・ダメージと表示の差、複数効果の可読性
- 大量ユニット：選択対象と陣営の見分け、重なり、味方/敵の境界
- iPadサイズ/Google Sitesサイズ：カードの横幅・文字・HP・ボタン・画面の見切れ・触れる面積
- 対戦終了/再戦：試合結果表示、ロビー復帰、古いユニットが残らないか
- 実測FPSと映像上の体感は**別のレビュー項目**として残し、1つの数値で品質を断定しない

## 初回レビュー：通常戦闘と130体ストレス戦闘

[ローカル戦闘レビュー成果物](https://github.com/8mahi8/shokoku-sensen/actions/runs/39377842196)（WebKit動画+通常/ストレス10画面）。

- 通常戦闘：開始直後の配置・カード・城壁・砦・敵ユニットが画面内で大きく破綻していない。操作不能や継続的な描画停止もテスト上では確認されず。
- 130体の極端な密集戦：装飾の描画以前に兵士や武器が互いを強く覆い、混戦の状況を読み取りづらい。**これは意図的なストレス配置で、通常マッチで130体密集するとの証拠ではない。** 安易なゲームバランス変更はせず、可読性改善候補として記録。
- WebKit 130体：約7.9FPS、95パーセンタイルフレーム間隔約170ms、画面更新最大243ms、126体が移動。Chromiumコンパクト：約29.3FPS、95パーセンタイル約34ms、最大50ms、111体が移動。
- **これらはGitHub Actionsのヘッドレス描画であり、実学校iPadではない。** 通信遅延も含まないローカル描画の比較なので、「学校のゲストが7.9FPS」と誤解しない。
- 実Firebaseのゲスト側録画と校内実機プレイは別途確認し、実測とユーザー感想が衝突した場合は要因を切り分ける。

## 初回レビュー：実Firebaseゲストの録画

[実Firebase WebKitゲストの動画・スクリーンショット](https://github.com/8mahi8/shokoku-sensen/actions/runs/39378327202) をダウンロードし、動画の時系列と、準備フェーズ・召喚後・1200ms後・通信復旧直後の画像を実際に目視レビューした。

- ルーム入室 → 準備 → 召喚 → 通信復旧 → 再戦の遷移で、全画面を覆う不正なエラーダイアログや恒常的な画面停止は見つからなかった。ゲーム側の自動検証も合格
- この録画の可視場面は主に**準備段階と開戦直後**。中盤の多数の発射物・頻繁なユニット交戦時に滑らかかどうかは、現資料だけで合格判定できない
- 診断オーバーレイが右上の戦場を隠すが、これはQAで `?perf=1` を有効にした状態だけ。通常対戦では常時表示しない
- WebKitヘッドレスで描画FPSが低下する場面がある。学校iPadのゲストFPSだと断定できないため、実機の体感改善の最終確認が必要
- **次のレビュー重点**は「オンライン実戦の中盤で双方が多数召喚した場面」の録画と時間差画面。実機からの短い画面収録があれば、ゲーム側だけでなく学校の環境に固有のカクつきも判別しやすい
