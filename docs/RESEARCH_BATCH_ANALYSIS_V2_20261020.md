# 小国戦線III｜対戦データを貯めて一括研究する v2

## 運用の考え方

- 2026-10-20学校実機フィードバック以降、**身内プレイ用の匿名記録は初期ON**。参加者に記録を明示し、双方とも対戦前にOFF、対戦中にも停止可能。自動学習、アップロード、対戦履歴表示、ランキングは作らない。
- 学校iPadとGoogle Sitesの負荷を増やさない。ゲーム内で行う処理はホストの合法なカード使用記録と約8秒おきの簡略状態サンプルのみ。
- **人間の行動を集計することと、強いBOTであることを証明することは別**。戦術を作った後の未知条件の独立対戦と人間による体感が必要。

## 対戦するとき

1. 初期設定で匿名記録ON。開始前に許可ボタンを押す必要はない。学校で遊ぶ友達にも、カード使用や戦況が匿名で記録されると説明する。**嫌な参加者は開始前にOFF、試合中は停止ボタンで即時撤回可能。** どちらかが無効化した対人戦はホスト側の未確定記録を破棄し、ゲームは続けられる。
2. 対人でゲストがBOT操作へ切り替えても試合は続く。制御モードの変化をレコードで区別する。
3. 対戦終了時に**「対戦データJSONを保存」「JSONコピー」「共有」**のいずれかからファイルを持ち帰る。Google Sitesのiframeなどでダウンロード/共有ができないときは、表示されるJSONテキストをコピーできる。
4. 保存される最新8試合を超える前に書き出す。プライベートモードや埋め込み側の制限で `localStorage` が保持されない場合は、**画面を閉じる前に必ず書き出す**。データ削除は参加者が個別に操作できる。
5. 学校の友達へ、データ収集への参加・共有を強制しない。ほかの人の名前・ルーム番号・実日時・端末ID・チャット内容は保存しない。

## 収集ファイルの確認とまとめ方

Node.js 22以降（外部ライブラリ不要）。例:

```bash
node tools/research/analyze-match-batches.cjs shokoku-match-batch-1.json shokoku-match-batch-2.json
node tools/research/analyze-match-batches.cjs --out report.json shokoku-match-batch-1.json shokoku-match-batch-2.json
```

- 統計は **人間同士／人間対BOT／途中切替／不明**に分類。過去版の対戦ログなどBOT操作の情報を特定できないものは`unknown`のまま残す。
- 複数回書き出した同じ試合は匿名データの内容に基づいて完全一致の重複を除外する。
- 合算するのは勝敗、陣営別・カード別の合法行動数、行動時点での資源平均、対戦時間など。個人勝率ランキングや「最適解」への自動変換はしない。
- 一部の試合には記録上限 `overflow`（500アクション・80状態サンプル）がある。集計出力の`incompleteOrTruncated`を確認する。
- 記録されることを友達に説明し、共有を拒否する意思を尊重する。JSONの開発者への共有は任意で、分析後も研究用ファイルを勝手に公開しない。

## 安全なバージョン扱い

- 実記録のトップレベルschemaは現在`1`のまま後方互換を維持。新しいメタデータ:`matchType`（表示用）と `guestControlHistory`（実際の判定の根拠）。
- `matchType`という文字列だけを信用して「人間同士」と断定しない。解析ツールは制御履歴から保守的に再分類する。
- `guestControlHistory`がない昔のオンライン試合、ゲスト制御がunknownに変化した試合、32回を超えて制御切替履歴が省略された試合は`unknown`に分ける。
- `guestControlHistory` はゲーム経過秒と `human` /`bot` /`unknown` のみ。人を識別できる情報は記録しない。
- BOT相手の情報は、既存のルーム `players/guest.botControl` 真偽値でホストへ伝える。ルーム本体の既存コマンドや対戦同期と分離。**本番Firebase Rulesは編集しない。**
- WebKit/Safari相当のブラウザと実Firebaseの2ブラウザ検証（記録初期ON／片側OFF／再有効化／BOT操作切替）を実施。学校実機Google SitesでのJSON保存・コピー・共有の最終確認は別途必要。

## 2026-10-20 学校検証後の公開候補

- ユーザーの学校実機確認で報告されたゲストラグと「新しいゲーム」の停止対策を、`main` 由来の独立した修正ブランチで検証。
- Google Sitesに貼るHTMLとGitHub Pages用モジュールは同期。ルーム v2 は旧ページの混在を避けるための区別で、ログschemaは v1 のまま。
- Firebase応答に依存しないルーム画面への即時復帰、ラウンド更新時の状態・seqリセット、旧ルーム通知ガードを追加。
- 状態更新間隔は軽い戦闘で約125ms、50体以上で約180ms。実際のゲストFPSや回線によって体感は変わる。
- **GitHubへの修正統合はGoogle Sitesへの公開完了を意味しない。** 友人との実対戦を検証して初めて公開版完成と扱う。
