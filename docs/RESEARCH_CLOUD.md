# 小国戦線III｜匿名対戦ログの自動蓄積（開発ブランチ）

更新: 2026-10-21。**開発PR #22上の未公開実装。Firebaseの実際の研究保存権限は未設定・未検証。main・学校Google Sitesの既存HTMLは変更しない。**

## 目的と設計範囲

友達同士の対戦を、ゲーム管理者が参加していなくても研究用に蓄積できるようにする。既存の1vs1、BOT、キャラHP/攻撃力調整には触れない。自動的なBOT学習や無検証のバランス変更は行わず、データを**後から一括分析**する方式。

- 従来の**端末内記録**は変わらず、対戦者双方の研究記録同意が必要。終了時にホスト端末のローカルストレージへ最大8試合を記録し、JSONを手動で書き出せる。
- 新しい**研究用クラウド保存**は完全に別のチェックボックス。**両プレイヤーが同じオンラインルームで明示的にONにしたときだけ**、ホストが試合終了後に1件保存。初期OFF。**安全なサーバー環境の構成まではチェックボックス自体を無効化**（`window.SHOKOKU_CLOUD_RESEARCH_READY` 未設定）し、書き込みも拒否。ローカル記録に同意していてもクラウドには勝手に送らない。
- 対戦途中にどちらかが同意を撤回したらその試合は送信しない。試合開始後に新しくONにはできない。退出・再入室したら同意は初期OFFへ戻る。
- 送る情報は試合モード、人間/BOT区別、カードの使用時間と種類・位置・手札情報、8秒ごとのエネルギー・部隊位置とHP・城/砦状態、勝敗と継続時間。**名前・ルーム番号・端末ID・IP・チャット・Googleアカウント情報は試合データに含めない**。ただしプレイ時刻とゲームの行動情報自体は個人と結びつく可能性を完全には否定できない。
- ホストは端末ローカルで最大1日12試合分だけ送信を試行。1レコードのJSONは65,000文字以下、記録サンプル最大80・カード行動最大500。これらは正常な端末での上限であり、**悪意ある匿名クライアントへのサーバー側の容量制御ではない**。
- 保存先パスは既存対戦ルーム `/shokokuRooms1v1` とは別の `/shokokuResearchV1/<random 128-bit+ key>`。BRAWLの `/rooms` などには触れない。
- 1レコードに `createdAt` と `expiresAt`（送信端末日時から約14日）を設定。**expiresAtがあるだけではFirebaseは消去しない**。専用の管理者クリーンアップが必要。

## 公開する前に管理者がすべきこと

1. **Firebaseの実際のセキュリティルールを確認**。まずプロジェクト `mygame-df915` の既存ルールをバックアップし、既存の対戦用アクセスやBRAWLを壊さない。研究ツリーだけに新しい設定を追加する。**この作業はこのチャットから実施していない**。
2. 研究ツリーを**一般ブラウザから読み取れない**ようにする。Firebase RTDBでは親ノードに `.read: true` があると、子に `.read: false` を置いても非公開に戻せない。これを含めて実際の親ルールから確認する。実装は毎回 `/_privacy_probe` の匿名読取を試し、読み取れた場合は**クラウド送信を拒否**する。読取が「PERMISSION_DENIED」でなければ必ず停止する。これだけで書き込み濫用まで防げるわけではない。
3. 研究ツリーへの**匿名書き込みは、そのまま許可すると無制限の第三者による迷惑投稿や料金増大の危険がある**。本番向けにはサーバー側の検証・レート制限（たとえばApp Checkを有効にした制限付きCloud Functions/Cloud Run受付など）が必要。Firebase Rulesで単純に `.write: true` とすることは推奨しない。
4. 将来の管理用削除・取得はFirebase Console/Admin SDKなど、**管理者権限だけ**で行う。研究データを公開GitHub Actionsのログや平文artifactへアップロードしない。専用秘密鍵が必要な場合はGitHub Actions **Secret**だけに設定し、チャット・GitHubのソースコード・Google Sites HTMLへ貼らない。
5. 上記の権限・非公開読取・書込濫用対策・実DBでの安全確認が終わった場合に限り、HTMLの**ゲーム通信コードより前**へ `<script>window.SHOKOKU_CLOUD_RESEARCH_READY=true;</script>` を置いて、管理者が版を発行する（通常の `online.html` なら `online-net.js` 読込より前）。現時点の開発版には置いていない。
6. **公開版はユーザーがGoogle Sitesへ最新版の単体HTML全文を貼り付けて公開して初めて反映**される。現段階のPRやテスト結果は実運用開始を意味しない。

## 管理・保存期限

- `.github/workflows/online-research-retention.yml` は、**mainブランチへ採用された場合のみ**毎日17:00 JST前後に起動する設計。管理用Secret `SHOKOKU_FIREBASE_MAINTENANCE_SA_JSON` が無い場合は何もせず終了する。**開発ブランチの現段階では動かない**。
- `tools/research/prune-expired.py` は、管理者の認証で `expiresAt <= now` の研究レコードだけを1実行あたり最大50件削除する。自動運用にはFirebase Rulesの `shokokuResearchV1` に `expiresAt` のインデックスが必要。試合本体やBRAWLツリーは削除しない。
- 管理者が任意の記録を削除するには、Firebase Consoleから `shokokuResearchV1` の該当レコードを削除できる。**ゲーム内の「記録削除」はローカル保存の削除であり、既に送信済みのクラウド分まで消すボタンではない**。プレイヤーから削除要望が来た場合の本人確認・管理者処理は公開前に準備が必要。
- 利用者へ「研究用クラウドへ残る」「送信したデータは端末内停止だけでは取り消せない」「削除依頼先」の説明を事前に示す。

## 管理者が取得してBOT研究する方法（現段階）

1. Firebase Consoleから**管理者として** `shokokuResearchV1` サブツリーだけをJSON形式でエクスポート（第三者への公開は禁止）。この書き出しは現時点で**手動**。ChatGPTは勝手に管理者Firebaseへ接続できない。
2. ローカルPCで `node tools/research/import-firebase-export.cjs firebase-admin.json shokoku-batch.json` を実行。有効期限内でデータ形式が正しい匿名記録だけを取り込み、予期しない識別子等を捨てる。
3. `node tools/research/analyze-match-batches.cjs shokoku-batch.json` で勝敗傾向・カード使用と人間/BOT別の統計を出す。実戦の因果検証ではないため、BOT改善候補は別にA/B対戦して判断する。
4. **収集の自動化**と**ChatGPTへの安全な自動転送**は別の問題。後者には管理者だけが読める専用連携または非公開保存先が必要。現時点の公開GitHubリポジトリに生のログを置いて代用しない。

## 運用の合格条件

- 初期状態・片側だけON・端末内記録だけON・片側が途中でOFF・研究ツリーが公開読取可能・保存失敗では**クラウドへの記録が0件**。
- 両方が事前同意、管理者が非公開書き込み環境を構成済み、投稿制限と期限削除が動作する場合にのみ、試合終了後のホスト記録を1件送る。
- 実Firebaseで非公開研究ツリーの書き込み・削除・管理側取得を確かめるテストは**未実施**。既存のオンライン対戦を壊さないことを開発CIで検証してから検討する。
