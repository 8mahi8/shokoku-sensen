## 2. 今後のキャラ（ユニット）AIは「シンプル」を最優先

2026-10-28本人希望：「キャラのAIは別に複雑にしなくていいよ。ちゃんとシンプルなのが大事」。

- **目的**: ユニットがわかりやすく、役割に忠実に、意図しない不自然な動きをせず戦うことで、召喚する**位置・タイミング・相性**というプレイヤー側の判断を生かす。
- **求めない**: 複雑な経路探索、長期予測、ML/学習、毎フレーム多段評価、隠れた協調行動、追加の直接指示UI、無断での性能最適化・演出変更。
- **既存仕様を出発点にする**: `nearbyEnemy`（敵を選ぶ、既存ロックを維持）、`getFort`（占領先）、`unitStep`（normal / guard / capture）。既に動いている単純な挙動は残す。
- **改善するなら具体的な不自然さを一つずつ証明する**: 実際に困る例を再現し、最小限の単純な条件分岐で直し、元の予測可能性と軽さを保てるか確認する。
- **陣営の公平性**: 人間の青・赤で同じ挙動、BOTの強さは召喚判断側で調整し、敵味方のユニット物理に隠れたハンディを設けない。
- **性能保全**: 学校で合格したホスト/ゲストの軽さ、操作レスポンス、通信方式を壊さない。新たなデータ収集、認証、対戦履歴、追加通信はしない。
- **バランスは別段階**: AIとHP・攻撃力・コストを同時変更しない。競技性は「高度な自動判断」の多さではなく、プレイヤーが行動を予測し戦略を立てられることから生む。
- **BOTの戦略AIとユニットAIは別物**。今回はユニットAIを単純・予測可能にする話であり、BOTを勝手に大改修する意味ではない。

## 3. 次の順序（この記録自体はゲーム本体を一切変更しない）

1. 安定版を固定し、現行版との比較基準にする（**本日実施**）。
2. ユニットAIの現状と「実際に困る行動」を最小限の再現ケースで点検。**問題がなければ直さない**。
3. 具体的な問題が見つかった場合に限り、1挙動ずつシンプルな修正案を設計し、開発ブランチで実装・比較。
4. ユニットAIの挙動が安定してから、対戦バランスとBOTの改善を検討。
5. 学校iPadで再確認し、変更後のものを安定版と交換するかは本人が判断する。
