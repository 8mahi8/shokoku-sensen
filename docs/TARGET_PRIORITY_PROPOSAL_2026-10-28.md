## 1. 目標
- **AIは簡単に、キャラの個性はデータ設計で出す。** 新キャラ用の条件分岐を量産しない。
- 全キャラに**城／砦／敵キャラ**の3つの対象優先度（0〜3）を与える。特別な兵種のみ「大型キャラ」「飛行キャラ」などのカテゴリを任意で追加。
- 射程内の相手を攻撃すること、索敵内の相手に向かうこと、行動型（攻撃/占領/迎撃）の移動制限、ロックオン中の目標維持を**別の責務**として扱う。
- 後出しでおとりを置く読み合いを残す：**攻撃先は毎回の攻撃直前に再選択（B案）**。目標への移動ロックは別。

## 2. 優先度の定義【本人発案を整理】
| 数値 | 攻撃射程内 | 索敵内・射程外 |
|---:|---|---|
| **0** | 無視 | 無視 |
| **1** | 攻撃できるが、同じ射程内の上位には譲る | 接近対象にしない |
| **2** | 攻撃できる。射程内で1より優先 | 移動候補になる |
| **3** | 攻撃できる。射程内で最優先 | 移動候補の中でも最優先 |

攻撃の有無と移動先は2つの独立した問い。**射程内の1を攻撃できるなら、索敵だけに入る3を追うために攻撃をやめない**。攻撃後にどこへ移動するかは移動目標の処理で判定する。

選択手順：
1. 生存・敵味方・飛行への攻撃可否・砦占領能力・敵砦の所有者・移動の前後方向などから合法性を判定。
2. 射程内の優先度1以上から「**優先度が高い→同値なら距離が近い→同値なら安定ID**」で攻撃先を選ぶ。攻撃のたびにやり直す。
3. 索敵内・射程外の優先度2以上から、同様に移動目標を選ぶ。ただし**移動時の目標ロック（後述）を優先**。攻撃型は背後へ追いかけず、迎撃型は召喚地点中心の固定索敵円を使う。
4. 移動目標がなければ、攻撃型・占領型は**戦場の前方へ進む**。迎撃型は召喚地点へ戻る。
5. **城の優先度0は「城を攻撃・追尾する対象にしない」という意味**。戦場の前方へ進むために城方向の基準座標を使うこととは区別する。従って「城0・砦0・敵兵3」の特化兵も探索のため前進できるが、城に着いても攻撃しない。

- ライダーは本人の直近訂正「城3・砦3・敵1」を残す。**城・砦が同優先なら初回発見時の最寄り**。決定した移動目標を基本保持する方針は本人が今回了承。
- 工兵は、ライダーと明確に役割差を作るため**城2・砦3・敵1**に調整した提案。砦を見逃せば敵城に進む。
- 迎撃衛士・ゴーレムは城**1**にすれば、索敵内だが射程外の城を**自発追跡しない**ことを優先度で直接表現できる。射程内に敵兵2がいれば城より敵兵を優先。なお以前の「射程内のすべてから最寄り」の厳密適用からは少し変わるため**確認が必要**。

- **基本歩兵の砦2**は射程外でも見つけた砦へ近づくことを意味する。以前の「砦に寄り道しないかもしれない」という暫定検討とは異なるため、**最重要の本人確認事項**。

## 4. 特別な対象カテゴリの拡張
例：
```js
// 3つの基本欄は必須。追加欄は任意。
const targetPriority = {
  castle: 3,
  fort: 0,
  unit: 2,
  largeUnit: 3
};
```
- 敵大型は`largeUnit`が明示されていれば`unit`より**それを優先して上書き**し、なければ`unit`へフォールバック。値は**加算しない**。
- `largeUnit:0`なら通常敵`unit:2`でも敵大型だけ無視できる。新しい「飛行敵3」「特定サイズ0」なども同じ発想で実現できる。
- 今後カテゴリが複数重なったとき（例：大型かつ飛行）は特例の競合解決が必要。現在は単一カテゴリの上書きのみを確定候補とし、必要性が生じてから明示的な優先解決順を考える。
- 以前の「全ての大型キャラは敵大型を優先する」という本人の合意は、**大型兵種を新しく設計するときの共通テンプレートとして`largeUnit:3`を付ける**方法で維持できる。ゲーム実行時に隠れたサイズ加点を計算しない。
- 基本8設計項目はそのまま。優先度は**追加のキャラデータ**で、9番目の必須分類軸に無断変更しない。

## 5. 移動目標ロックと攻撃先再選択【同一視しない】
- **攻撃の対象**：毎攻撃の直前に射程内候補から優先度・距離で選び直す。新しく射程に入った歩兵で次の弓兵攻撃を誘導できる。
- **移動の目標**：たとえばライダーが索敵範囲内の同優先3で最寄りの砦を選んだら、**その砦を占領／味方所有化するか、到達不能・消滅するまで保持**。城の方が後から少し近くなっても毎フレーム切り替えない。本人了承。
- 移動目標が砦でも、砦が射程外で敵兵1が射程内ならその敵に反撃できる。反撃に合わせて移動目標を敵兵へ変更しない。
- 攻撃型の敵兵追撃などの移動ロックを全く固定すると、優先度と距離の「最も近い」原則を長期間無視しうる。**まずは固定目標の保持は砦・城などの静的建物だけ**を明確な正本として適用し、移動する敵兵は現在候補を必要に応じて再評価する案。
- 「射程内の敵への攻撃」と「砦・城に向かって前進」を同時に許すか、攻撃アニメ中だけ足を止めるかは動きの見た目と現行速度に影響するため、実装前の検証事項。**優先度だけで自動決定しない**。

## 6. テスト観点と確認
アルゴリズム単体（ゲーム本体未変更）で14条件の仮想候補を評価し、優先度比較の期待結果が14/14一致。
- 射程内の優先1の敵を、索敵内で射程外の砦3より先に攻撃する。
- ライダーの城3と砦3が同時射程内→近い方。移動目標も初回見つけた時は同順位なら最寄り。
- 工兵の砦3は、城2がもっと近くても砦へ向かう。
- ゴーレムの射程内大型3が通常敵2より優先。
- 重戦車の城3と大型3が両方射程内→近い方。片方が索敵内だけなら射程内を攻撃。
- 迎撃衛士の城1は攻撃射程内なら城を攻撃するが、索敵内だけでは追わない。
- 歩兵の砦2は索敵内で射程外でも追跡候補になる。
- 対空不可等の不合法対象は優先3でも除外する。

**これはターゲット比較ロジックだけの検証。実戦AIの移動、砦占領の成否、ホスト/ゲスト、学校iPadではまだ未検証。**
