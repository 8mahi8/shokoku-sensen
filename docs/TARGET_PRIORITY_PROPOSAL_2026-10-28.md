# 小国戦線III｜対象優先度0〜3と拡張カテゴリの設計案 v0.2

開発ブランチ：`perf/online-guest-snapshot-diagnostics-20261020`、Draft PR #22。学校安定版・main・Google Sites・Drive・Firebase Rulesには変更しない。

## 1. 本人の提案の核心
- 各キャラにまず **「敵城」「砦」「敵キャラ」** の3カテゴリの優先度を設定する。
- **特殊なキャラだけ**「大型キャラ」「飛行キャラ」「特定の別カテゴリ」などの狭いカテゴリを追加する。全キャラに一律の大量な欄を増やさない。
- 同一対象が「敵キャラ」と「大型キャラ」の両方に該当したら、**特化カテゴリの優先度を上書き適用する**（提案）。両方の優先度を加算せず、単一の値で選択する。
- 将来、すべて無視して特定の対象だけを優先するキャラは他カテゴリ0・そのカテゴリ3で表現可能。例：敵城3・砦0・敵キャラ0＝城以外を攻撃／追跡対象にしない。
- 「キャラの個性は設計データで出し、共通AIは単純に」という方針に合う。

## 2. 0〜3の意味（本人案を整理）
| 優先度 | 射程内 | 索敵内だが射程外 |
|---:|---|---|
| 0 | 無視 | 無視 |
| 1 | 攻撃対象になる | 追跡しない |
| 2 | 攻撃対象になる | 追跡候補になる |
| 3 | 優先攻撃候補になる | 優先追跡候補になる |

1. **先に射程内の合法候補から選ぶ**（優先度1以上）。優先度が高い順、同順位なら距離が近い順。射程内に1がいれば、遠方の索敵内3を追うより1を攻撃。
2. 射程内に合法候補がいなければ、**索敵内で追跡できる候補**（優先度2以上）から同様に選んで接近する。
3. 射程内も索敵内も候補がなければ行動型の通常行動（進軍、帰還など）。ターゲット攻撃は攻撃ごとに再選択（既存合意B案）。
4. 対空可否・敵味方・HP・占領能力などの攻撃可能性と行動型の移動制限は別に適用。優先度だけを理由に「占領型が敵兵を追う」「迎撃型が城へ歩く」とはならない。**この二層の設計は必要か本人最終確認事項**。
5. 同距離・同値では安定ID等の決定的な順序を使用。旧AIにある隠れた距離/群れボーナスを無断で残さない。

### 他の既存キャラへの推定例（まだユーザー未承認）
- 重装工兵：ライダーと同じ城3・砦3・敵1にできる（占領型の共通テンプレートとして）。
- 魔導重戦車：城2・砦0・敵2、追加・大型キャラ3にできる（全大型に大型優先を付ける以前の合意と整合）。
- 迎撃衛士：城2・砦0・敵2と設定しても、`guard`移動制限で城へ歩いて行くことは禁止。城が射程内にあるときの攻撃可否は以前のQ3が残る。
- 基本歩兵：城2・砦2・敵2と設定すると、砦が索敵内で射程外のとき**追跡候補になる**。以前の「砦へ寄り道しない攻撃型」方針と異なるので、勝手に追跡禁止条件を追加しない（要本人確認）。

## 4. プロパティ構造の提案
```js
// まず3つ。特殊対象は必要なキャラだけ追加する
targetPriority: {
  castle: 3,
  fort: 3,
  unit: 1,
  // largeUnit: 3, // 例：特別な大型を優先するキャラだけ
}
```
- **カテゴリの継承／上書きの提案**：敵大型なら `largeUnit` を定義していればその値、なければ `unit` を使う。0による特例除外も可能。単純な「設定があるものを優先」、未設定なら通常分類にフォールバックする。
- 将来の新カテゴリには、名称と**どの敵を対象とするか**という判定だけを追加すればよい。追加カテゴリ同士が同じ敵に重なる場合（例：大型かつ飛行）は、どちらを適用するかの仕様（より具体的なカテゴリ順序など）を別途決める。現在は過剰設計を避ける。
- `targetPriority` はキャラごとの**追加データ**として保持。既存の8基本項目は勝手に9項目へ変更しない。

## 5. 実例
- ライダー：砦（優先3）が射程内＆敵兵（優先1）が射程内→砦を攻撃。
- ライダー：砦（優先3）が索敵内＆敵兵（優先1）が射程内→敵兵を攻撃。移動目的の砦は保持。
- ライダー：城と砦が**両方索敵内・双方3**→**近い方**へ向かう、というのが本人の「同順位は最寄り」から導かれる。砦より城が近ければ城を選ぶ。これが意図通りか要確認。
- ゴーレム：通常敵2と大型敵3が両方射程内→大型敵を攻撃。
- ゴーレム：通常敵2は射程内、大型敵3は索敵内・射程外→通常敵を攻撃。
- その他を0、城だけ3にした攻城特化兵→敵兵と砦を無視して敵城へ向かう（ただし通常進軍目的との関係を要設計）。
- **重要**：キャラで定義した「大型3」は全ての大型が自動的に備えるという意味ではなく、**ユーザーが必要なキャラへ設定するデータ方式**。以前の「大型クラスは全員大型優先」の合意と両立させるには、デフォルトの大型用テンプレートに付けるか、各キャラに明示設定する方針を実装時に決める。

## 6. 実装に向けて残る最小限の確認
