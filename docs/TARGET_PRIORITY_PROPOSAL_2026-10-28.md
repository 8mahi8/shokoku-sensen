## 0. 設計目的【本人意向・最重要】
- 進撃型／占領型／迎撃型の既に決めた基本動作（前進、砦優先の役割、防衛地点、後退追撃の制限など）を壊さない。
- これまで「もし砦と城が同時にあったら？」「大型だけ優先できる？」と都度追加していた**対象の狙い方**を、全キャラ共通の小さなデータ表で表現する。
- まずは `castle`（敵城）・`fort`（中立／敵砦）・`unit`（敵キャラ）の3欄、必要なキャラだけ `largeUnit`（敵大型）等の欄を追加。
- キャラの個性は能力・コスト・行動型・攻撃方式・優先度で出し、各ユニットに新しい専用AIや複雑なロックを無闇に追加しない。

## 1. 優先度の意味【ユーザーの発案】
| 値 | 攻撃射程内 | 索敵範囲内だが射程外 |
|---:|---|---|
| 0 | 無視 | 無視 |
| 1 | 攻撃候補 | 無視（追いかけない） |
| 2 | 攻撃候補 | 追跡／接近の候補 |
| 3 | 優先攻撃候補 | 優先追跡／接近候補 |

対象選択の順序：
1. **射程内の候補があれば先に攻撃**（優先度1以上から、数字の大きい順、同じなら近い順）。
2. 射程内に合法な攻撃候補がなければ、索敵内の優先度2・3から同じ方法で移動先を選ぶ。
3. 候補なしなら、その行動型の従来の平時の行動。攻撃のたびに攻撃対象を再選択する既存B案は維持。
4. 特殊な目標ロックは**追加しない**。同優先度ならその時点の近い方。数学的な同距離なら決定的IDを使うだけ。
5. 他に「行動型による索敵の位置（迎撃型は召喚地点中心の固定円）」「前方へ進軍」「背後へ追いかけない」「攻撃可能な地上／空中」「砦を占領できるか」といった既存の基本制約は従来通り保持。**優先度値のために新しいAIを追加する意図ではない**。

## 2. 僕の全9兵種の優先度推奨【新提案・本人最終確認待ち】

| キャラ（ID） | 行動型 | 城 | 砦 | 敵キャラ | 特別欄 |
|---|---|---:|---:|---:|---|
| 基本歩兵 (`infantry`) | 進撃 | 2 | **1** | 2 | なし |
| 魔導射手 (`archer`) | 進撃 | 2 | 0 | 2 | なし |
| 偵察ライダー (`scout`) | 占領 | **3** | **3** | **1** | なし |
| 重装工兵 (`engineer`) | 占領 | **3** | **3** | **1** | なし |
| 迎撃衛士 (`sentinel`) | 迎撃 | **1** | 0 | 2 | なし |
| 制圧機兵 (`suppress`) | 進撃 | 2 | 0 | 2 | なし |
| 守護ゴーレム (`guardian`) | 迎撃 | **1** | 0 | 2 | `largeUnit:3` |
| 浮遊ドローン (`drone`) | 進撃 | 2 | 0 | 2 | なし |
| 魔導重戦車 (`tank`) | 進撃 | 2 | 0 | 2 | `largeUnit:3` |

**設定理由：**
- 基本歩兵は一般進撃の `castle:2,unit:2` を保ち、`fort:1` だけ加える。**遠くの砦へ寄り道しないが、射程内なら攻撃可能**。優先度1なので射程内に優先2の敵がいればそちらを攻撃。歩兵専用の特殊AIは不要。
- 射手・制圧機兵・ドローンは**同じ進撃型の2/0/2**。射程・速度・範囲攻撃・飛行で役割差が出る。制圧機兵の密集優先スコアは新しいモデルに勝手に持ち込まない。
- ライダーと工兵は**同じ占領型の3/3/1**。速度・HP・占領力（工兵2／ライダー1）で個性差が出る。前回の提案でAIが勝手に設定した「工兵は城2・砦3」は撤回。
- 迎撃衛士とゴーレムは**城1**を提案。敵城が**射程内なら**攻撃できるが、射程外の城を追いかけないことを、既存の守備型に余計な特殊処理を加えず数値化する。敵兵2なので両方射程内のときは敵兵を優先。**以前の本人のゴーレム城2は例としての記載であり、現在は役割から再設定を求められているため1を提案**。ここは採用判断前に確認したい。
- ゴーレムと戦車は**大型敵3**の追加欄で、従来の「大型同士を優先して狙う」方針をデータ化。重戦車に城3を独断で足さない。城へのダメージ2倍は既存の `siege:2` として保持。城2と敵大型3が同時射程内なら大型3が優先する。
- 優先度2や3は「攻撃力・ダメージ倍率」ではない。能力値は変更しない。

## 3. 行動型はそのまま【本人の意図を明記】
- **進撃型**：敵城方向へ進軍。索敵した攻撃可能な敵へ前進、背後の敵は射程内でなら攻撃するが、後退して追いかけない。歩兵の砦1は射程内だけを対象とする。
- **占領型**：通常は前進し、砦や敵城が索敵範囲に入ったら優先度に従う。**同じ3ならその時点の近い方**。敵兵1は射程内にだけ反応し、射程外を追わない。砦がまだ射程外なら、射程内の敵兵1に攻撃してよい。特別なロックオンはなし。
- **迎撃型**：召喚地点中心の固定索敵円（半径は本人が設定した各 `vision`）。索敵対象へ迎撃し、対象がなければ召喚地点へ帰る。固定円の外でも自分の攻撃射程内の敵には反撃可。敵城1により遠くの城へ移動する理由は生まれない。

**補足**：占領型の従来設計資料には「見つけた砦の目標を保持」という古い合意が残るが、**本人は後から明示的にロックなし、同順位は近い方と訂正した**。実装時は後発の意図を優先。これ以外の3行動型の原則は変えない。

## 4. 拡張欄の仕組み
```js
targetPriority: {
  castle: 2,
  fort: 0,
  unit: 2,
  // 必要な兵種だけ追加
  largeUnit: 3
}
```
- 同じ敵が`unit`と`largeUnit`に該当する場合は**具体的な`largeUnit`が`unit`を上書き**。数値を合計しない。未定義なら`unit`の優先度へフォールバックする。
- `unit:0,largeUnit:3`にすれば、通常の敵兵を全て無視して敵大型のみを狙うこともできる。もちろん別カテゴリに固有0を設定して無視も可能。
- 複数の特別カテゴリが同じ敵に一致する条件（大型かつ飛行等）の衝突解決は、実例が生じたときに定義する。現段階で無理にAIを複雑化しない。
- 今回の優先度は、既存のキャラ設計8軸に**追加する対象選択のデータ欄**であって、3行動型の増設ではない。

## 5. 設計単体でのシナリオ確認
19ケースの簡易JSで、優先度比較・索敵と射程の先後・役割側の基本制限を確認し**19/19一致**。
例：
1. 歩兵の遠い砦1は追わない。射程内に砦1だけなら攻撃。敵2と砦1が射程内なら敵2を攻撃。
2. ライダー／工兵：砦3と城3が両方索敵内なら近い方。射程内の敵兵1は、索敵内の砦3より先に攻撃。
3. 迎撃型：城1は射程内だけ攻撃、射程外の城は追わない。固定索敵円外の敵へは追撃しない。
4. ゴーレム：敵大型3と通常敵2が両方射程内なら大型3。通常敵2が射程内、大型3が射程外の索敵内なら通常敵2を攻撃。
5. 戦車：敵大型3と城2が両方射程内なら敵大型。城2と普通の敵2が射程内なら近い方。
6. 制圧機兵：複数の敵がいても隠れた密集優先を足さず、優先度と距離で選ぶ。
7. 攻撃不可能な飛行敵は優先度3でも選ばない。

**これらは優先度の簡易ロジックチェックであり、既存 `online-game.js` を改修して実走・iPad検証したものではない。**
