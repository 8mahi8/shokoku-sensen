# 小国戦線III：iPad操作・WebKit表示の自動検証（2026-10-15）

この記録は開発版 `develop` のみを対象とする。公開版 `main`（`e3330a0564bda8460bf746232e75abf7130b1bfe`）は変更しない。

## 何を実際に動かしたか

`.github/workflows/online-ipad-visual.yml` から `tests/online-touch-interaction.cjs` を実行。Playwright の Chromium と WebKit の両方で、1194×834（横向き）、820×1100（縦向き）、900×520（Google Sites 相当の埋込）を検証する。

- 実ブラウザの `touchscreen.tap` でカード選択／解除と召喚（支払い・青軍ユニット発生）を確認
- `page.mouse` の連続移動と `pointerType="touch"` の合成 PointerEvent で、カメラ移動とスワイプ誤召喚ゼロを確認
- 550ms 以上の長押しで詳細パネルが表示され、カードが誤選択されず、閉じられることを確認
- 約1.1秒の rAF 間隔を記録。画面画像（操作後・スワイプ後・長押し・低DPR）と WebM 動画を成果物に保存
- Firebase SDK 読込を意図的に遮断してソロモードで実行。実オンライン通信は `tests/online-browser-live.cjs` が別途検証

初回 PASS と動画・画像： https://github.com/8mahi8/shokoku-sensen/actions/runs/38750093622

**注意：これはPC上のheadlessブラウザであり、物理iPad／実機Safariの速度・タッチ感触を検証したものではない。** 合成touchスワイプも物理操作そのものではない。

## 性能観測

観測窓1.1秒の rAF コールバック数を記録。CI負荷による変動があるため、絶対FPSや実機性能を表す数字ではない。

| WebKit（同一CIジョブでの比較） | 画面 | DPR 1.45 | DPR 1.0 |
| --- | --- | ---: | ---: |
| run 38751646904 | 横 1194×834 | 16 | 18 |
| run 38751646904 | 埋込 900×520 | 28 | 34 |
| run 38751646904 | 縦 820×1100 | 18 | 23 |

同じテストのChromiumは両DPRで約65–67フレーム。WebKitはソフトウェア描画や仮想実行環境の影響が大きく、実機の予測はできない。

固定背景をCanvasへ一度描いて再利用する比較（run 38751085800）は、WebKit 3サイズでキャッシュ有無の中央値に一貫した大きな差がなく、主ボトルネック解消には至らなかった。スクリーンショット確認ではカードやモーダルの破綻は見つからなかった。

## 現在の開発版での対応

- 静止した背景模様のみ一度生成して再利用。所有砦や召喚境界は引き続きゲーム状態に従って描画
- 通常Canvas DPRの上限1.45を維持し、プレイ開始後に約3.4秒のフレーム数を測定
- **計測が38fps未満でCanvas DPRが1.0超の場合のみ**、Canvas内部の描画密度を1.0へ下げる
- 解像度の変更はそのタブの試合中1回だけ。高速端末では変更なし。位置・当たり判定・経済・Firebaseの通信形式は変更しない
- 画質低下とfps向上のトレードオフ。頭打ちの原因が解消したとは限らず、実機の試遊が必要

## 次の確認事項
