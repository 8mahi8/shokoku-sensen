# 小国戦線III｜新キャラ追加しやすさの監査（2026-10-29）

対象：開発ブランチ `perf/online-guest-snapshot-diagnostics-20261020`、Draft PR #22。コード観察とユニットAI・学校配布コードのテスト。**新キャラは追加していない。カード循環・デッキ構築の設計と実装は許可されておらず、一切着手していない。**

## 結論
- **戦闘AIの共通化は合格**：3行動型 `normal/capture/guard` と `targetPriority:{castle,fort,unit}` により、既存の選択器 `priorityFor/selectPriorityTargets/unitStep` を再利用可能。
- **キャラを追加してゲームで正しく見せる工程は、まだ1か所設定では完結しない**：アート、攻撃演出、学校用HTMLと値調整欄、BOTの召喚判断に既存ID依存が存在する。
- 次のキャラを実際に追加する際は、**戦闘コアを増殖させず、設定と描画・配布の整合性チェックを小さく改善する**。ただし今回は監査とテストのみ。

## 本体コード監査（現実の依存関係）

| 領域 | 現状 | 新キャラ追加時の注意 |
| --- | --- | --- |
| ユニット定義 | `online-game.js` `CLASSES` | 数値性能・3行動型・対象優先度を宣言する。HP・攻撃力・コストをAI検証と同時にバランス変更しない |
| ターゲット選択 | `priorityFor`／`selectPriorityTargets`／`unitStep` | 共通。必要な独自特性は既存 `largeUnit/flyingUnit` のような宣言的欄を使う。新たな特殊カテゴリが必要な場合だけ共通traits側を設計・検証する |
| 召喚／HP／ダメージ／対空／範囲 | `deploy`／`fire`／`CLASSES` 参照 | 基本処理は再利用可能。既存の飛行巻き込み制限などは戦闘仕様として維持 |
| 攻撃アニメの長さ | `MOTION.attack` がID別辞書 | 新ID未登録だと攻撃アニメ時間が不定。今回CIへ値の網羅チェックを追加 |
| 通常アートとカード肖像 | `v3-art.js` の `SPRITES`、`UNIT_COLORS`、`UNIT_SCALE`、`BODY_HEIGHT` | 新ID未登録時は歩兵アートへ暗黙フォールバックし、HPバーのY座標がNaNになり得る。今回CIへ登録漏れ検出を追加。専用アートと肖像の目視審査は別途必要 |
| 演出の個別条件 | `v3-art.js` の `u.key==="drone"`（飛行表示）、`guardian/tank`（大型演出）および `online-game.js` の砲弾・斬撃演出IDリスト | 新しい飛行・大型・射撃キャラを同じ見た目にしたい場合、既存ID条件では自動認識されない。**戦闘AIの問題ではなく表現層の改良余地** |
| BOTの召喚戦略 | `botExpertAction` 以下に `scout/engineer/guardian/tank/... ` のID指定が多数存在 | 新IDの特性を自動的に評価するBOTではない。追加時に実際のBOT戦で召喚判断を検証し、必要時のみ最小限修正。BOTの全面改修はしない |
| 既存固定カード循環 | `DECK_IDS` と `HAND_SIZE` による現行仕様 | **新ユニット定義を追加しただけではプレイヤーの手札に現れない**。ここを変える設計議論・コード作業は現在禁止。ユーザーから将来別途明示指示があるまで保留 |
| 学校配布 | `online-ipad.html`／`online-embed.html` 内に本体がインライン展開、先頭に `SHOKOKU_UNIT_STATS` | モジュール版の変更後に両HTMLのソースとキャラ値欄を一致させる必要あり。既存 `online-smoke.cjs` が本体コード全文とHP/攻撃力一覧の一致を検査。自動生成ツールの存在は確認できず、更新の手作業リスクが残る |
| QA専用混戦生成 | `seedMassBattle` は9体の固定配列 | 開発用の大量生成シーンに新キャラが自動参加しない。通常の対戦・共通戦闘エンジンとは区別する |

## 今回実施した拡張性テスト
- `tests/online-unit-target-priority.cjs` 内の旧 `Object.keys(CLASSES).length===9` 制約を外し、既存9体の定義が維持されれば新IDを許すよう修正。
- **仮の追加ID（本番に残さない）**で、進撃型が敵を追う、占領型が砦へ向かう、迎撃型がアンカーの索敵と帰還を使う3例を確認。専用AI分岐は1つも追加しない。
- `tests/online-smoke.cjs` に、現在登録されている**全ユニット**へ `MOTION.attack`／`SPRITES`／`UNIT_COLORS`／`UNIT_SCALE`／`BODY_HEIGHT` が揃っていることを確認するチェックを追加。欠落するとCIで見つかる。新キャラを実際に描画した検査ではない。
- 既存34シナリオ＋3追加で **37シナリオ成功**。スモーク・シミュレーションも合格： [GitHub Actions #40785901827](https://github.com/8mahi8/shokoku-sensen/actions/runs/40785901827)。
- 本体の `online-game.js`、`online-net.js`、`v3-art.js`、学校用HTML、既存の学校Google Sitesページ、main、stable、Firebase Rules、既存Driveは変更していない。

## 今後、新キャラを採用する時のチェックポイント（まだ実装しない）
1. 8項目と独立のHP・攻撃・速度・コスト・特性・対象優先度がデータで表現できること。既存行動型と0〜3優先度で済むなら新しい個別 `if` は作らない。
2. 新IDの前後進・砦・飛行・射程内/索敵内・特殊優先を仮想局面で検査。左右チームでも同様。
3. 名前・描画・アニメ時間・肖像・HPバーのサイズと位置が登録され、実戦の見た目と学校iPadでの負荷が適切であること。既存アート制作ガイド `docs/CHARACTER_PIPELINE.md` を参照。
4. BOTの既存ID依存が当該キャラに影響する場合だけ調整。
5. 学校貼付けHTMLのコードと先頭の性能値欄がモジュール原本と一致し、スモーク・シミュレーション・ブラウザ2画面が回帰合格。**学校版の公開更新はユーザー指示があるときだけ**。
6. **カードの組み込み方は今回決めない。** 既存カード循環・将来のデッキ構築についてはユーザーの別指示まで議論・下準備とも行わない。
