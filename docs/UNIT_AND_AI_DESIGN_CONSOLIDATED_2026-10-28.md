## 0. 目的と開発原則【合意】

> **ユニットAIはシンプルで予測可能に。キャラの個性は行動型・優先度・ステータス・攻撃特性で表現する。プレイヤーの技術は、どこにいつ何を召喚するかに残す。**

- **3行動型はこれまでの設計を基本的に維持**し、新しい優先度を理由に作り直さない。
- 各キャラの「何を狙うか」を0〜3の数字で表現する。新しいキャラごとに固有AIの分岐を付け足す前に、数字の組み合わせで表現可能か検討する。
- ハードコードされた密集補正・大型補正・過去のターゲットを無条件に保持する補正などは、必要性を吟味し、基本的に明確な優先度と距離判定へ整理する。**範囲攻撃の威力・巻き込みそのものは変更しない。**
- BOTの戦略（どのカードをどこに召喚するか）と、召喚後に全プレイヤーへ公平に適用される**個々の兵士のAI**は別の層。
- AIを変える際にHP・攻撃力・コスト・召喚数・速度を同時に調整しない。学校で体感の良かった通信・描画を保つ。

## 1. キャラ設計の8つの基本項目【合意】

| 項目 | 意味 | 現行JSの対応 |
|---|---|---|
| ① 階級 | 小型／中型／大型 | `size` |
| ② 行動型 | 進撃型／占領型／迎撃型 | `behavior: normal/capture/guard` |
| ③ 移動タイプ | 地上／飛行 | `flying` |
| ④ 攻撃射程 | 数値。近距離／遠距離の二択に固定しない | `range` |
| ⑤ 攻撃方式 | 単体／範囲 | `splash`、`splashScale` |
| ⑥ 占領能力 | 不可=0／可能=1以上。数値が占領力 | `capture` |
| ⑦ 攻撃間隔 | 秒／攻撃（小さいほど高速） | `cool` |
| ⑧ 索敵範囲 | 数値。攻撃射程から自動計算しない | `vision` |

そのほかにコスト・HP・攻撃力・速度・召喚数・使用回数・対空能力(`hitAir`)・対象の当たり判定半径(`r`)・対城倍率(`siege`)などの独立した性能がある。  
**対象優先度(`targetPriority`)はこれらと並ぶ追加のキャラ設定データ**であり、「新しい行動型」を作るものではない。8項目の分類を全面的に置換する意味もない。

- **占領型**という行動目的と、**砦を占領できる**という能力は別（基本歩兵は進撃型でも `capture:1`）。
- 地上／飛行と対空攻撃可否も別。長射程の新キャラは原則対空可能として設計しやすいが、`hitAir`は個別に明示する。射程だけで自動付与しない。
- 対空可能な範囲兵でも、現行ゲームの巻き込みが飛行敵に当たるかは別の仕様。AI再設計に混ぜない。

## 2. 対象優先度0〜3【合意・今回の中心】

全キャラにまず**敵城`castle`／砦`fort`／敵キャラ`unit`**の3種類を持たせる。

| 優先度 | 自分の攻撃射程内に存在 | 自分の索敵範囲内だが射程外 |
|---:|---|---|
| **0** | 無視 | 無視 |
| **1** | 攻撃の対象にはなる | 無反応（自分から追わない） |
| **2** | 攻撃の対象になる | 接近・追跡の候補になる |
| **3** | 2より優先して攻撃候補になる | 2より優先して接近候補になる |

### 全員共通の比較手順

1. **合法性を確認**：敵味方、敵兵の生存、砦所有者、対空能力、占領能力、行動型の索敵・移動制約を先に評価。物理的に攻撃できない対象は数字が高くても狙えない。
2. **射程内の候補が優先**：射程内に優先度1以上の合法な対象があるなら、その中で**優先度が高い→同じなら近い**の順に攻撃対象を選ぶ。**射程内1を無視して、遠くの索敵内3に向かって攻撃機会を捨てない。**
3. 攻撃射程内に対象がないとき、索敵範囲内の**優先度2以上**の合法な接近対象から同じ比較順で移動相手を選ぶ。ここでも3は2より優先、同値は最寄り。
4. 対象がなければ行動型ごとの平時の行動へ（進撃・占領は城方向へ前進、迎撃は配置地点へ帰る）。
5. **攻撃するたびに射程内の候補を選び直す（B案）**。後から出した歩兵が射手の次の攻撃先を変えられる。既に成立した攻撃を取り消すことはない。
6. **特別な移動目標ロックオンは追加しない**。城と砦が同じ3で共に候補なら、その時点で近い方を狙う。等距離の細部は安定したID順等で決定して揺れを避ける。**旧文書の「ライダーは一度決めた砦を最後まで保持」は撤回。**
7. 攻撃ターゲットの判定と移動挙動は同じ条件ではない。例えば遠い砦3へ向かう途中で敵1が射程内に入れば、その攻撃機会には敵1を攻撃できる。余計な「攻撃型専用・占領型専用の特別優先スコア」は足さない。

### 必要なキャラだけ追加する特殊な対象カテゴリ

標準3欄に加え、たとえば`largeUnit:3`、将来は`flyingUnit:3`など**追加カテゴリの値を必要なキャラだけ定義**できる。

```js
// ゴーレムなど、敵大型だけを通常の敵より優先したい場合
targetPriority: {
  castle: 1,
  fort: 0,
  unit: 2,
  largeUnit: 3
}
```

同じ敵大型は「敵キャラ」にも該当するので、**より具体的な`largeUnit`が定義されていれば`unit`を上書き**する。優先度は加算しない。未定義なら`unit`へフォールバック。`largeUnit:0`なら他の敵キャラに反応しても敵大型だけ無視できる。  
他カテゴリを0、城だけ3にすれば「城しか攻撃しない兵」もデータで作れる。新カテゴリの組合せが複数重なる場合（大型＋飛行など）の衝突ルールは、そういうキャラを実際に作る際に設計する。**現時点で不要な状態機械・優先度4以上・ロック条件を作らない。**

## 3. 3行動型の基本動作【合意・変更しない】

### A. 進撃型（`normal`）
- 基本は敵城方向へ進む。索敵範囲内の合法な優先度2/3の敵は接近候補にできる。
- 背後の敵も射程内なら攻撃可能。ただし背後へ引き返して追跡しない（C案）。
- 基本歩兵は`fort:1`なので、**遠くの砦に釣られず、射程内に入った時だけ砦を攻撃できる**。砦のためのキャラ専用AIは作らない。
- 他の進撃型は概ね城2・砦0・敵2。キャラ間の射程・速度・範囲攻撃・飛行・攻撃間隔等で個性が出る。

### B. 占領型（`capture`）
- 砦と敵城を狙い、敵キャラは射程内なら反撃するが、射程外の敵を追跡しない。個性の**対象選択部分は城3・砦3・敵1**で表現する。
- 砦は自分の**既存の索敵範囲`vision`**に入って初めて接近対象になる。固定半径300などで遠い砦へ強制誘導しない。**見逃して城へ突撃するのも意図した戦術。**
- 城3・砦3は同順位なので、同時に認識した場合は**近い方**。砦に向かっていたとしても、別対象がその時点で同順位かつ近ければ選び直してよい。**特別なロックオンなし**。
- 砦は索敵内だが射程外、敵キャラ1は射程内→**敵キャラを攻撃可能**。砦と敵がどちらも射程内なら**砦3を攻撃**。砦に向かうのに敵への反撃を無理に禁止しない。
- 移動方向（前進中心・背後を強引に追いかけない）と砦/敵城の選択を、距離・射程・索敵値・優先度の自然な組合せで処理する。占領型のために隠れた固定ターゲットを持ち込まない。

### C. 迎撃型（`guard`）
- **召喚地点`anchorX/anchorY`中心の固定索敵円**。円の半径はそのキャラの`vision`。守備型が動いても索敵円は移動しない。
- 円内にいる合法な優先度2/3の敵キャラを迎撃し、対象がいなくなれば配置地点へ戻る。**移動範囲を硬くクランプしない**。敵が固定円から外れれば追跡しない。
- 固定索敵円外でも、**自身の射程内にいる敵にその場で反撃できる**。ただし追いかけない。
- **敵城は優先度1**：射程内なら攻撃対象になり得るが、遠い城を追って進軍しない。射程内に優先度2の敵キャラがいれば城より敵を優先。
- 大型のゴーレムは、通常敵キャラ2を基本に**敵大型3を上書き**する。守備目的を放棄せず、大型を優先して迎撃する。

## 7. 受入テスト／未検証の端のケース

### 実装時の必須シナリオ
1. **歩兵**：索敵内の砦1は追わない、射程内の砦1は攻撃できる。砦1と敵2が両方射程内なら敵2を優先。
2. **進撃型**：後方に敵がいても射程外なら引き返さず、射程内なら攻撃できる。前進・砦への不要な寄り道なし。
3. **ライダー／工兵**：城3と砦3が両方索敵内なら最寄りを選ぶ。砦3が射程外、敵1が射程内なら敵に攻撃可能。砦と敵が両方射程内なら砦。
4. **非ロックオン**：城と砦の距離順が変わったら再評価する。砦が味方所有になったら対象候補から除外する。遠い砦のために追加の300半径探索をしない。
5. **迎撃型**：索敵円は召喚地点中心で固定。円内の合法な敵2へ接近。円外なら追わない、射程内だけ自衛。敵がいなくなれば帰還。敵城1は射程内なら攻撃、遠くの城は追わない。
6. **大型**：敵大型3と通常敵2が両方射程内なら大型。射程内の敵2と索敵内の大型3なら射程内の敵2を先に攻撃。
7. **重戦車**：敵城2と敵大型3が両方射程内なら大型。敵城のみ射程内なら対城2倍攻撃。制圧機兵は隠れ密集優先を持たず、範囲性能だけで集団に強い。
8. 対空可否、飛行・地上、同距離IDの安定性、砦の所有者変更、左右チーム対称、BOTと人間で戦闘AIが同じ、学校用HTMLでの動作。
9. FPS・ホスト計算量・ゲスト描画・操作レスポンス・通信の安定版との差異を確認。**ヘッドレスWebKitの数字と実機iPadの体感を混同しない**。

### 実装時の小さな境界事項（仕様の本筋は確定）
- 既存の`range + target.r`など、対象の当たり半径を含む攻撃可能判定と「最も近い」の定義を一致させる。
- 「攻撃間隔が残っているが射程内の敵に攻撃できない瞬間」の移動・停止と、砦へ向かいながら反撃するときのアニメーションは不自然にならないか固定場面で見る。
- 固定索敵円境界・同距離選択が繰り返し切り替わる問題は、**まず再現してから最小限の対策**。勝手にロック・複雑な粘着スコアを追加しない。
- **索敵内・射程外**が`vision`と`range`の数値関係で曖昧になる場合、射程内はいつでも先に評価する。
- 特別カテゴリの重複（大型かつ飛行）は現状の9体に必要なルールではない。将来導入する際にだけ優先順を明文化する。

**優先度のみの簡易判定は前段で19条件照合済み。これはゲーム本体テストではない。** 統合AIの本当の合格には本体のユニット行動テスト・学校実機の確認が必要。
