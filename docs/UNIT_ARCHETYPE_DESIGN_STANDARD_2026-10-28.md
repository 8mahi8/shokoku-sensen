## A. 設計の最重要ルール：項目を混同しない

ユニットは以下**8つの基本項目**で説明する。①〜⑥は属性・役割、⑦は戦闘の時間的特性、⑧は索敵の距離的特性。キャラ固有の攻撃力・HP・索敵範囲・速度などは別の数値項目として持つ。

| 項目 | 選択肢 | 決めること | 原コードでの対応 |
|---|---|---|---|
| ① 階級 | 小型／中型／大型 | コスト帯・体数・頑丈さ・存在感の設計上の基準。絶対的な防御倍率ではない | `size: small/medium/large` |
| ② 行動型 | **攻撃型／占領型／迎撃型** | **どこへ進むか、敵にどの程度反応するか**。攻撃型=従来の「通常進撃型」 | `behavior: normal/capture/guard` |
| ③ 移動 | 地上／飛行 | 攻撃される側として飛んでいるか。攻撃可能な対象とは別の軸 | `flying` |
| ④ 射程 | **数値** | 攻撃が届く距離。近／遠の二択タグは設計標準から削除 | `range` |
| ⑤ 攻撃方式 | 単体／範囲 | 主対象1体だけか周囲にも巻き込みがあるか | `splash`, `splashScale`（未指定なら単体） |
| ⑥ 占領能力 | 可能／不可能、占領力 | 前哨基地を実際に攻撃・奪取できるか | `capture > 0` で「可能」、数値が占領力 |
| ⑦ 攻撃頻度 | **攻撃間隔（秒）** | 次の攻撃までの時間。頻度・後出しターゲット変更の機会に影響 | `cool`（seconds per attack）。攻撃回数/秒は `1 / cool` の派生表示 |
| ⑧ 索敵範囲 | **数値** | 新たな敵を発見し、追跡候補として認識できる距離。攻撃射程や追撃上限とは独立 | `vision`。**射程から自動計算しない** |

**特に重要**：「②占領型」は砦を優先して行動する性格のこと。「⑥占領可能」は砦を奪える能力。両者は別物。
例：**基本歩兵＝攻撃型 + 占領可能（capture:1）**、偵察ライダー＝占領型 + 占領可能（capture:1）。迎撃型が占領不可なのも現時点の兵種設計によるもので、型の定義上の同義語ではない。

他の独立属性：
- **攻撃できる対象**：地上のみ／地上＋空中（現コード：`hitAir`）。
- **例外能力**：敵大型の優先迎撃、密集部隊への優先攻撃、敵城への倍率 `siege` など。乱造しない。
- **性能**：`cost`,`qty`,`limit`,`hp`,`damage`,`cool`,`vision`,`speed`,`r`。戦闘AIと別の数値定義。
- **カードUIと絵**：上記から表示文言を作る。キャラの見た目やガルド差し替えは戦闘ルールと混同しない。

## B. 本人の新方針：遠距離は原則対空可能

- **射程が比較的長い新キャラを設計する際の既定値**：`hitAir: true`（地上・空中の両方を直接狙える）。数値の閾値で自動分類しない。
- **例外は許可**：例外を作るなら「この遠距離兵は地上のみ」とカード説明に明記し、戦術上の理由を示す。従来の近距離キャラも将来対空可能としてよいが、個性として明示する。
- **射程数値だけを見て実行時に自動的に対空へ切り替えない**。明示フィールド `hitAir` を正本にする。既存キャラや古いセーブ/スナップショットとの整合性を守る。
- **飛行であるか `flying`** と **対空可能か `hitAir`** は別物。現在の飛行ドローンは遠距離で対空可能。
- **範囲攻撃の対空と巻き込みはさらに別**：安定版 `fire()` は `hitAir:true` の範囲兵が飛行敵へ**直接攻撃**できる一方、`splash` の巻き込みでは飛行敵を除外。今後「空にも範囲巻き込み」が必要なら別途明示的な仕様検討が必要。**今回自動変更しない**。
- 安定版の遠距離4種（魔導射手／制圧機兵／浮遊ドローン／魔導重戦車）は、すでにすべて `hitAir:true`。今回の方針を守るためのゲーム修正は不要。

## D. 新しいユニットを作るときの共通設計票

作成順（上から決めると役割がぶれにくい）：
1. **主な仕事を1行**で記述：例「安く砦を守る」「飛行ユニットを迎撃する」「前線を突破する」。
2. **8つの基本項目を全て設定**する。未定欄は残さない。
3. **対空の可否**を明記。遠距離の初期値は○。
4. **ゲームで何を狙うか**を1行で表現する：共通の「対象の選び方」を基準に、例外が必要なら1つだけ理由を書く。B案「攻撃ごとに再選択」が現在の第一候補で、実装・調整はまだ未確定。
5. 性能を設計：コスト、体数、使用回数、HP、攻撃力、**攻撃間隔（秒）**、索敵範囲、射程、速度、範囲など。
6. **得意な相手・苦手な相手**が言えるか。既存の近い役割のキャラとの違いを説明する。
7. AIと性能を同時に調整せず、安定版・実機体感・青赤対称性への影響を検証する。

**テンプレート（設計票のみ、実行コードではない）：**

```yaml
id: new_unit
name: 新ユニット
concept: 一言で説明できる仕事
size: small | medium | large
role: attack | capture | intercept    # 現在の normal | capture | guard へ対応
movement: ground | air
attackRange: 100                      # 数値。近距離／遠距離の二値タグは不要
attackIntervalSeconds: 1.5           # 次の攻撃までの秒数。実装時は現行 cool に対応
sightRange: 190                      # 索敵範囲。実装時は現行 vision。射程と独立
attackShape: single | area
targets: ground | ground_and_air      # 射程が長いキャラでは後者が基本、明示設定を維持
capturePower: 0                       # 0=占領不可、1以上=可能。別のcanCaptureフラグ不要
specialTargetRule: nearest            # 特例があれば、カードで説明できる単一ルール
strength: 得意な相手や状況
weakness: 弱い相手や状況
# 詳細性能: cost / qty / limit / hp / damage / speed / splash ...
```

**データの一貫性チェック（将来の実装候補）**
- `role=capture` なのに `capturePower=0` なら設計ミスとして差し戻す。
- `attackShape=area` なら範囲半径と巻き込み係数が必要。`single` は範囲指定なし。
- **射程は正の数値**で指定し、射程が長いキャラの対空可能は設計上の既定候補とする。射程のみで `hitAir` を自動計算せず、実フィールドは独立設定。
- **索敵範囲は正の数値で独立指定**し、射程に応じた自動計算を必須としない。近距離の迎撃型でも広い索敵範囲を持たせられる。ただし **索敵できることと追跡できることは別**。迎撃型のアンカー防衛半径や占領型の目的制限に従う。
- **攻撃間隔は正の秒数**とし、`attacksPerSecond = 1 / attackIntervalSeconds` は派生情報にする。範囲巻き込みがある場合、単純な DPS 計算だけで集団戦の強さを評価しない。
- `canCapture` は `capturePower>0` から自動表示、二重定義しない。
- 3種の行動型の範囲・反撃条件はキャラの個別実装ではなく共通のルールで扱う。
- 攻撃先の原則は、現時点で **B案「各攻撃の直前に合法な候補から最寄りを選び直す」**が本人の第一希望。**暫定案であってゲーム実装は未変更**。移動中の標的保持、占領型が砦を優先する条件、迎撃型の守備圏、ゴーレムの対大型優先などの例外を別途精査する。
- 攻撃モーション途中のキャンセルはしない。攻撃が成立してから次の攻撃までの `cool` を使用する。攻撃間隔の長いキャラほど後出しのおとりへの**実際の攻撃先反映が遅くなる**ことをQAで確認する。
- 役割と特性の組み合わせを新たに発明した場合も、データ入力による追加を基本とし、新しいAI本体は必要なときだけ追加する。

## E. AIとの境界：少数の共通ルールで表現する

- **攻撃型 (normal)**：敵と交戦しながら前進。捕獲可能なキャラには現行同様、砦への対応余地がある。
- **占領型 (capture)**：砦を優先して前進。遮る敵には反撃し、砦がなくなれば普通に前進。
- **迎撃型 (guard)**：配置位置を中心に敵を迎撃。いなくなれば戻る。
- 攻撃できる敵の判定は共通：敵/生存/対地対空/視界/位置/射程/必要なら守備圏。
- ターゲット切替は **B案「次の攻撃ごと再選択」**を第一候補として検討中。移動中にどの敵へ近づくかの再計算まで攻撃間隔に縛るべきかは未決定。大型優先や密集優先などの特例は「必要性・説明可能性」を確認して残す。
- 「占領型」「占領可能」「砦へ攻撃できる」「敵城を優先」の語を混同しない。建物の選択と敵兵の選択順は後段で仕様策定。
- むやみに状態機械/行動ツリーを増設せず、`getFort`, `nearbyEnemy`, `unitStep` の3箇所の契約を明確にする。**現在は本体を改修しない**。

## G. 2026-10-28追記：攻撃間隔と後出しターゲット変更（検討中）

本人の第一希望は、定期的に0.25秒で変更するC案より、**B案：各攻撃を始める直前に攻撃対象を再選択**。したがって実装設計上は次の区別が必要。

1. **狙う相手（次の攻撃先）**：攻撃できる時点で、行動型の制限と攻撃可能対象を満たす候補から最寄りを選択。元対象を無条件で固定しない。
2. **近づく相手（追跡先）**：射程外のときは、攻撃間隔を待たずに合法な敵を探して移動できる必要がある。探索・移動と実際の攻撃先再選択を混同しない。この詳細は未確定。
3. **攻撃頻度**：コードでの正本は `cool`（秒/攻撃）。攻撃力 `damage` と独立して調整する。画面での表記は「攻撃間隔 1.65秒」とするのが分かりやすい。
4. **おとり戦術**：弓兵がドローンを狙っていても、次の攻撃時に歩兵が最も近い有効対象なら歩兵へ切り替わる（理想）。既に発射された攻撃や即時確定したダメージを巻き戻さない。
5. **反例**：攻撃間隔が2秒の戦車におとりを置いても、次の攻撃まで効果が見えない。これがゲームとして自然かはプレイテストで判定する。キャラの攻撃頻度による個性として受け入れる選択肢がある。

**この追記は設計検討の更新であって、ゲームのターゲット選択ロジックを更新したものではない。** 現行安定版は依然としてロック優先を保持する。比較資料：`docs/TARGET_RETARGET_EXTERNAL_RESEARCH_2026-10-28.md`。

## H. 2026-10-28追記：索敵範囲を独立した第8の基本項目に正式追加

本人の提案を受け、**索敵範囲 `vision` は全キャラ固有の基本設計項目**にする。射程 `range` から自動的に算出する案は採用しない。弓兵（射程153、索敵195）とゴーレム（射程52、索敵210）は矛盾ではなく、長射程と守備の広い発見範囲という独立した役割に基づく設計。

追撃距離／配置地点からの最大離脱距離は今後「行動型ごとの共通AIルール」として設計する。射程が長い敵に先制されること自体は相性・戦術として許すが、近接ユニットが敵を発見できないことによる不自然な無反応は検査する。

前に作成した検討資料 `docs/UNIT_SIGHT_RANGE_AND_COUNTERPLAY_PROPOSAL_2026-10-28.md` 内の「射程から索敵を自動計算する」案は、**この設計更新によって採用しない**。歴史的な検討記録としてのみ残す。

**今回の変更は設計文書のみ**。既存の各兵種の `vision` 数値、AIロジック、学校安定版は変更しない。
