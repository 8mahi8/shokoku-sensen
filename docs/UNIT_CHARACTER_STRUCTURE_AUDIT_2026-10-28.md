## この資料の目的と変更禁止事項
ユーザー希望「これはそもそものキャラの話にもなりそうだから、まずは今のキャラの構造を整理するか」および「AIは複雑にしなくていい、シンプルが大事」。
この資料は**現在の9兵種を事実として棚卸し**し、役割・狙う対象・行動・描画を切り分けて、今後の検討順を定めるためのもの。新規キャラ、性能、AIロジックの変更案を勝手に確定しない。

**安定版**：`stable/school-ipad-20261028-99a0d1d`（現在学校iPad実機でラグが気にならなかった版）。安定版ブランチ、`main`、Google Sites実運用版、Firebase Rules、Google Drive既存配布物には手を加えない。開発上の記述・調査だけをDraft PR #22の開発ブランチに記録する。

## 1. 何が「キャラ」を構成するか（現行実装）
| 層 | 現行の正本 | 意味 |
|---|---|---|
| カード・兵種定義 | `online-game.js` の `CLASSES` | 名称・小/中/大・必要資源・召喚回数・1回の体数・HP・攻撃力・攻撃間隔・射程・視界・速度・行動型・占領力・対空・範囲等 |
| 特別なカード | 同ファイル `SPELLS` と `CATALOG` | 範囲砲撃と防護結界は兵種ではなくスペル。2種類とも1ゲーム最大3回 |
| その場の個体 | `deploy` が `S.units` に生成する各オブジェクト | `uid,key,team,x,y,anchorX,anchorY,homeY,hp,attack,lock` など。各キャラに別のAIクラスが存在するわけではない |
| 戦闘・移動・行動AI | `getFort`, `nearbyEnemy`, `moveToward`, `unitStep`, `fire`, `hitUnit` | 共通の戦闘処理に `behavior` と性能フラグで枝分かれ |
| 見た目・演出 | `v3-art.js`, `gald-render.js`, `gald-source.html`, `online-game.js` の `drawUnit` | 役割/判定と別。ゴーレムの「ガルド」は追加兵種でなく同じ `guardian` の専用外観 |
| 通信 | `online-net.js` + `game.world()/game.apply()` | ホストが移動/ダメージ/狙う敵/勝敗を計算し、ゲストは状態を描画。ユニットの独立AI処理をゲストで重複させない |
| Google Sites配置物 | `online-ipad.html` / `online-embed.html` | 上記を1つのHTMLへ同梱。先頭の `window.SHOKOKU_UNIT_STATS` は全9兵種の **HP・基礎攻撃力だけ** を上書き可能。安定版では元の数値と同一 |

旧 `v3.js` と過去のREADMEのBOT版記述を**現在のオンライン対戦の戦闘正本と混同しない**。必ず固定版 `online-game.js` を先に確認。

## 3. 現在の行動型は実質3つ
- **`normal` 前進型（歩兵／射手／制圧機兵／ドローン／戦車）**：視認できる攻撃対象を選び追う。いなければ進軍し敵城へ向かう。歩兵に限り `capture=1` なので、条件に合う未占領砦へ寄って攻撃する分岐を持つ（砦までX距離245未満等）。**歩兵を占領専用型と一括りにしない**。
- **`capture` 占領優先型（ライダー／工兵）**：未占領の砦が候補にある場合は原則そこへ向かい、接近した敵兵への反撃を行う。現行の通常対戦は「進行方向の最も奥の条件合致砦」を選ぶ。最寄り砦を選ぶQA-only実験設定が既存であり、現在は公開対戦に使われない。候補砦がなければ一般前進分岐。
- **`guard` 拠点防衛型（衛士／ゴーレム）**：召喚したアンカー周辺の敵を狙い、対象が見当たらなければ配置場所へ戻る。ただし `nearbyEnemy` は敵城を候補に含むため、近い場合は敵城へ向かい得る。**設計通りかどうかは未判定**。

追加特性は独立した複雑なAIモードではなく、**行動とは直交するフラグ**：
- `hitAir`（対空可能性）、`flying`（飛行として攻撃候補から除外されるか）、
- `capture`（砦に与える占領進捗）、`splash/splashScale`（周囲への追加ダメージ）、
- `siege`（敵城への倍率）、`qty`（1枚で召喚する数）、
- `size`、`range/vision/speed/cool`（判定/見た目/移動・攻撃）。

## 4. 攻撃先の決定はどう動くか（現行の事実）
1. `nearbyEnemy` は視界と対空能力で敵候補を絞る。通常進軍兵は原則前方の敵。防衛兵は配置地点周辺の敵。
2. 一度選んだ敵 `u.lock` が生存・追撃条件内なら原則継続。ただしゴーレムは条件内の大型敵を先に見る特例あり。
3. 新しい敵を探す場合、基本の「距離」に、後方への補正、大型同士への優遇、制圧機兵の密集相手優遇を加算して比較。敵城も距離から補正した候補になり得る。**近い敵を常に狙う保証はない**。
4. `unitStep` が `behavior` によって「その敵を追いかけて攻撃／砦へ行く／戻る／敵城へ行く」を切り替える。
5. `fire` はその場で命中・HP・砦占領・敵城ダメージを解決。射手・砲撃系の`S.projectiles` は**描画用の弾であり、着弾待ちでダメージを計算する弾道物理ではない**。攻撃アニメのタイミングと内部ダメージ時刻を混同しない。
6. 範囲攻撃の**巻き込み**は現状飛行敵を除外。一方、対空可能な射撃の**直接命中**は飛行敵に有効。スペルの範囲砲撃は `spellStep` で飛行敵も対象（建物には無効）。
7. 城は `damage * siege(未設定なら1)`、前哨基地は `capture` で削り、砦HPは12。砦占領で召喚ラインが前進。城HPは3000、準備10秒、1戦300秒。通常の兵種は敵城を攻撃可能だが砦は `capture > 0` のみ。

## 5. 企画面での役割の重なり（欠点と確定はしない）
| 似て見える組 | 現在の差別化 | 設計上の論点 |
|---|---|---|
| 歩兵／ライダー／工兵 | 物量前進兼占領／高速占領／鈍足高耐久・占領力2 | 3種類の「砦への向かい方」が直感的か |
| 射手／制圧機兵 | 低コスト・長射程単体対空／高コスト・範囲対空 | どちらが「近い敵」「密集敵」を攻撃するかは説明可能か |
| 迎撃衛士／ゴーレム | 安めの近距離守備／重い対大型守備 | 防衛兵の追跡上限と城への接近例外が理解できるか |
| ドローン／戦車 | 軽い飛行突破／重い攻城遠距離火力 | 両方前進型でもどう対策するかが見えるか |

## 6. 改善する前の疑問・検証優先順位
**P1：役割が画面で予測できるか。**
- ライダー／工兵が手前の砦を無視して奥を狙うのは、プレイヤーにとって直感的か。既存QAの「最寄り砦」比較データを重複なしで活用。
- 衛士／ゴーレムが敵城へ向かう条件は防衛キャラのイメージと合うか。
- 歩兵の「前進型なのに条件付きで砦も狙う」挙動は自然か。

**P2：攻撃対象が理解できるか。**
- 射手／戦車／通常兵が近い敵ではなく城を選ぶ、または制圧機兵が遠い密集を選ぶ場面はどこまであるか。
- ゴーレムの「大型優先」が直前の敵ロックより強く、頻繁な切替を生まないか。
- 命中判定のタイミングと見た目の弾の到達時刻のずれは、読み合いの誤解につながるか（演出の変更とは別に判断）。

**P3：それぞれのキャラを選ぶ理由が成立しているか。**
- 似た役割の2〜3兵種に明確な長所・短所・対処法があるか。AIが変わると相性バランスも変わるため、数値変更は最後に。

## 7. シンプルな構造の整理案（**未採用**）
既存の3種類の `behavior` をまず維持し、新たなAIアルゴリズム・専用クラス・キャラ増加は行わない。
- **基本行動**：前進／砦占領優先／配置地点守備の3種類。
- **攻撃対象**：攻撃可能な対象（地上/飛行）を絞る → 既存ターゲットを維持 → 見失ったらシンプルな共通ルールで次を選ぶ。
- **個性**：移動速度、コスト、体数、HP、射程、占領力、対空、範囲、攻城。特例はどうしても必要なものだけ。
- **表示**：カード詳細に「移動目的」「攻撃可能対象」「ターゲット優先」を数語で説明できるのが理想。画面に追加UIを増やすことは前提にしない。
- **判定条件**：選択・配置から相手の次の行動を予想できること、青/赤で同じこと、同時に複数のシステムを変更しないこと、実機合格の軽さを維持できること。
