- 基盤: PR #5 の公開前3ジョブ品質ゲート、PR #8 の重複Actions抑制。RTDBホスト権威と `online-embed.html` の直接貼付運用は維持。
- **`main` と実際のGoogle Sites埋込コードを変更しない。** `develop` から作業ブランチで実装／回帰検証後、公開可否は本人が判断。
- **HP・攻撃力・コスト・射程・命中／攻撃タイミング・移動速度・AI・デッキ・飛行可否・砦／城の勝敗条件を勝手に変えない。** バランス判断は本人が実施。
- Firebase schema / DBパス / ホストの権威的ゲーム計算を変えず、ゲストの表示と見た目だけを改善する。BRAWLのパスは一切使用しない。

## V18の最小スコープ（着手時の優先順位）

### A. 戦闘の一目での読みやすさ

1. **命中や着弾の見分けやすさ**：既存 `S.effects`、`S.projectiles`、`S.spells.incoming` の描画層を活用。ユニット攻撃と範囲砲撃を色・形・持続時間の視覚表現で区別。新たなダメージ計算や効果判定はしない。
2. **高密度戦闘の識別**：既存の `renderCrowdedUnit` と陣営の足元マーカーを維持し、味方・敵、飛行・地上、大型ユニットを縮小iPad画面で識別できるか確認。装飾過多・閃光・画面揺れは避ける。
3. **予告と実際の攻撃の区別**：`drawSpellFields` に既にある「砲撃予告」「防護結界」を視認しやすくし、予告が命中を保証するような誤解を与えない。判定半径を変えない。

### B. 操作の誤解防止

- 召喚プレビュー `drawPreview` と、タップ操作 `arenaDown/arenaMove/arenaUp` の表示差を確認。スワイプ終了時に誤召喚しない現在の仕様を守る。
- 「命令送信中」「ホストが受理」「通信途絶」を取り違えない。既存のV17.1通信表示を使い、新しい通信要求は安易に足さない。
- 視認性改善は、情報を増やすより重なりと読みにくさを解消する方針。

### C. 品質／負荷の後退を防ぐ

- 既存の `terrainBase` 一度きりの背景キャッシュ、`denseSpriteCache`、`drawCullingEnabled`、`guestSimplifyVisuals`、iPad向けDPR制限、`presentRemoteUnit` の補間は維持。
- `paintGrandArrival` は大きなユニットに短い演出がすでにある。画面全体の点滅・長い視界遮断・揺れを追加しない。`prefers-reduced-motion` を尊重。
- 既存の `setupPerfPanel`（ゲーム名3回タップ、ローカル診断）を活用。FPS・最大フレーム間隔・描画時間・ゲスト更新Hzを同じ条件で前後比較。厳密な実機値は未計測なので架空のFPS目標を記載しない。

## 実装・レビューの進め方

1. **V18開始前ベースライン**：`develop` のSHAを確定し、`tests/online-smoke.cjs`、`online-sim.cjs`、`online-release-iframe.cjs`、`online-guest-performance-v15.cjs`、`online-touch-interaction.cjs`、`online-mass-battle.cjs`、`online-grand-arrival.cjs`、`online-fort-navigation.cjs` の既存結果を参照。未実行のものは成功扱いしない。
2. **最初の変更は視認性1点だけ**。`online-game.js` と `online-ipad.html`・`online-embed.html` の同期を維持し、小さな作業PRで差分を制限。必要なら表示専用のテストを追加する。
3. **反証レビュー**：青／赤両軍、ホスト／ゲスト、Safari相当WebKit／Chromium、Google Sites sandbox iframe、オフラインBOT、低DPR・130体高密度・低FPS・再戦で正常か、視覚的な確認と自動テストで調べる。
4. **性能と認知負荷を比較**：演出で重要なユニットや敵の弾が見えにくくなる、タップを奪う、CPUが重くなる場合は却下。音量やSE追加を前提にしない（学校で無音）。
5. **公開は別工程**：`release/v18-...` で同一コミットの品質ゲート3ジョブ（transport+bundle / Sites iframe+combat / real Firebase 1v1）をすべて成功させ、本人の明示承認のあとにのみ `main` 統合、GitHub Pagesの反映確認、Google SitesのHTML再貼付・再公開。実機の短い対戦確認は最後まで必要。
